## 实际界面闭环

主观战派生 141789850 在 p1=12 时调用 141A3E880(UIModule,成员 vector,0,p2,p3,p4,p5)，第三实参固定 0。其普通提示经 1400F72D0→140D5D290；成员事件经 1400F71C0→140D5CF30。两包装先尝试实战 Agent，再尝试观战 Agent 的活动状态；不是任何时刻都必有可用界面。

观战 Agent 实际构造 140D629E0 安装 1421CA0D8，slot16=140D662C0 返回 Agent+88h 指向资料的+350h。其 Show140D62FE0 在 140D633FD 把 AddonId512 写入临时 DWORD、调用 140D5D8E0，在 140D63413 保存返回的运行时 Addon ID 到上述+350h。因此两个提示 helper 所得 virtual16 结果确实能指向该观战战斗日志窗口，不把运行时 ID 直接等同固定表号 512。

本机显式工厂记录 511/512 名称分别 PvPMKSBattleLog/PvPMKSBattleLogSpec，同为 create14012F5F0；它创建 752byte 对象，ctor1413C6DA0 安装 14225B810。实际 slot51 OnRefresh=1413C7320。普通提示提交 3 个 AtkValue：[2,样式,格式化文本]；OnRefresh 取一条显示记录，把文本放其文本节点 26，并用样式选择组件动画。成员事件提交 10 项，[0]=1，经同一 OnRefresh 转 1413C7C20 处理。界面身份来自实际工厂和调用链。

## 成员事件的参数与边界

p2=1 按 312byte 步长从成员 vector 取得 p3/p4 两条记录，完整 64 位指针传给末端，Self p5 完整 DWORD 作为 eventValue。末端使用两条记录的队伍 byte+E8h、职业 byte+E9h，第一条姓名及 EntityId+E0h（与本机比较）形成条目并选择样式；再由实际窗口显示姓名、两个职业图形及 eventValue 数值。该数字没有独立文字单位，本轮仅称战斗日志条目数字，不凭玩法经验命名连杀数或伤害。两成员的施受角色亦先保留具体显示顺序，不仅靠函数位置猜杀人与被杀。

141A3E880 旧 C 曾出现*(_DWORD*)vector 加偏移的指针截断伪码；141A3E95E 与 141A3E965 实际以 QWORD [RSI]分别加到 R9/RDX，绝非 32 位指针。明确 1400F71C0 和 140D5CF30 成员实参为指针后重新导出，新鲜 141A3E880_sub_141A3E880.c 已恢复 *a2+312LL*index。旧推导不作为客户端截断证据。

这批新增细分网络语义，但尚尚未确认 0642 全部子命令及共享水晶状态枚举，确认总数保持 798/869。0649 的未知缓存与本日志数字没有已证对应，不作联想。
