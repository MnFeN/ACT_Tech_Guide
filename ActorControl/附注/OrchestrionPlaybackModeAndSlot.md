## 0415：更新播放模式的应答

仅 IndoorTerritory 存在时处理。p1 完整 uint32 先转 0/非 0 布尔；非零时以完整 p2 覆盖全局 142AF9124，零时保留旧值。之后仍通知 OrchestrionInn 和 OrchestrionPlayList 两 Agent。p3..p8 及独立 target 未读。

此前把 p1 写成“低 8 位状态”不准确：主收包比较完整 DWORD，因此 0x100 仍为 true。p2 也不是列表 ID、大小或当前行号，而是**播放模式**。

| p2/缓存值 | UI 文字与已证行为 |
| ---: | --- |
| 1 | 顺序播放，Addon7065 |
| 2 | 随机播放，Addon7066 |
| 3 | 单曲播放，Addon7067 |
| 0 | 修改确认提示也使用“单曲播放”；列表显示逻辑按无列表上下文处理，不能与 3 视为完全相同 |

依据：140E49850 返回此缓存；141070080 及 14106F6F0 的 UI 回调 32/33/34 直接选择这些值及对应 Addon 行。确认文案 7074 说明屋内其他人也会受到影响。

1400FCF70 通知 Agent228 虚+136 与 Agent250 的 14106F590；后者只在已激活且 AddonReady 时刷新，不无条件弹窗。p1 为 true 时还按内部模式检查重置本地操作状态。这里按实际赋值与刷新定义 p1，不把它解释成“启用播放列表”的永久开关。

## 040E：播放/停止子协议中的两个字段

p1 高 16 位为子命令 0 界面结果、1 播放、2 停止，低 16 位为管弦乐曲 ID。子命令 1 的 p4 拆分为：

| 位区间 | 语义 |
| --- | --- |
| 0..15 | Z 坐标压缩值；与 p3 高 16 的 X、低 16 的 Y 一起按 u16*2000/65535-1000 解码 |
| 16..19 | 播放模式，写同一个 142AF9124 缓存 |
| 20..23 | 通知分支选择；2 用 Log3433，其余继续按操作者与播放模式选择提示 |
| 24..31 | 当前播放列表零基槽号，写 142AF910A；不是播放模式 |

140E38B80 拆包后，可暂存到 Indoor 延迟消费，也可直接调用 140E499A0。后者原生参数已显式修正为 entityId、songId、position、playbackMode、playlistSlot、notifyType，以避免旧形式名误导。

独立 UI 证据 141071DB0：从 140E49930 读 playlistSlot，循环 8 个列表槽，仅在**曲 ID 相同且槽号相同**时为该行置播放高亮 4h。不同槽可能放同一曲，单靠曲 ID 不足。模式为 0 或当前曲目为 0 时，该 UI 将当前曲视为 0、槽号视为 FF，因此不会产生列表当前播放高亮；这解释了 0 和 3 虽共用单曲文字仍不可合并。
