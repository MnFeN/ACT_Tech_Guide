# 0138：采集点次数与服务器许可

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

| 参数 | 实际用途 |
| --- | --- |
| p1 | low16 与 30000h 合成 EventId，取得已存在采集点 handler |
| p2 | low8 同时覆盖 RemainingCount+30A 与 Count+30B |
| p3 / p4 | 未读取 |

p5..p8 及 target 未用。handler 找不到时不创建。140E8B230 还无条件写 handler+312=1，即打开资源指定的服务器许可。次数按 byte 截断，不限制到资源默认 Count；没有额外读取 p2 高位。

## 许可与次数是独立检查

140E8B610.Setup 将 GatheringPoint 原始+17 bit0 写+311，同时清+312。140E8B830 先拒绝 Type0、直接接受 Type3；其他类型在+311 非 0 且+312 为 0 时拒绝。0138 设置许可只能解除这一项，探知状态、资源子类别、等级等后续门控仍然存在。

140E8B7E0 再把通用资格与(RemainingCount 非 0 或虚 280 例外)做 AND。因此同一次收包同时恢复次数和许可，两者均有实际用途。不能只说它更新了一个未读取的计数副本。

实际虚表 1421DD950 和 1421DF500 的槽 280 是 140E8C180 恒 false；1421DEB80 的槽 280=140E954E0，在 handler+428 指针存在且该对象+5D8 flags 满足 bit18=0、bit19=1 时可放行。140E9D520 在 handler+78 WORD 不是 FFFF 时只用通用资格，否则也追加次数/虚 280。因此不能把“次数为 0 必不可用”推广到所有子类。

## 资源条件的命名边界

完整 5857 行资源中 776 行配置该许可要求，映射 64 个 Base，相关总体与真实物品证据见 GatheringPermissionRowPopulation.md。该资源 bool 的官方名称仍是 Unknown1；从客户端能精确定义它为“此点需服务器许可”。服务器根据任务还是其他玩法条件授予许可，并不是本包另一个未知参数，客户端本分支没有该判定代码。本文不为它编造“已接取宇宙任务”之类超出证据的名称。

0139 清+312；0180 按 p3 高 16 是否非 0 写+312；017C 没有写此位。这里已经闭合本类别的初始化、设置、撤销与最终可用性读取链，四参数用途可确定，故 0138 转为已核对。此结论不表示已经证明所有服务器授予条件。

没有 0138 回放样本；依据为当前 CN 客户端原生代码、实际虚表和本机完整资源总体。
