# 073B／073A.p2：剧情所用元素等级的独立文本证据

## 新证据为何足以命名

此前已确认状态+4 为完整 uint32、按 3..50 的数值门槛比较，但仅凭数列将它猜为元素等级不足。本轮没有将旧推断直接改标签，而是建立实际事件身份，再检查同一事件实际调用的具名等级文本。

141A96220 按完整 CustomTalk 事件 ID 选择伴随处理器。扫描静态对象指针而不是猜邻近虚表后，定位以下三个真实对象与 slot6 方法：

| CustomTalk 事件 | 内容 |
| --- | --- |
| B01C7 / 721351 | **静态 holder / vtable**：1428D9218 / 142425210<br>**方法**：141A98B50<br>**原生等级门槛**：3、5、13、17<br>**实际资源脚本**：CtsErkEureka1EventKrile_00455 |
| B01F2 / 721394 | **静态 holder / vtable**：1428D9290 / 142425648<br>**方法**：141A996D0<br>**原生等级门槛**：21、23、25、29、35<br>**实际资源脚本**：CtsErkEureka2EventKrile_00498 |
| B0200 / 721408 | **静态 holder / vtable**：1428D92C8 / 142425840<br>**方法**：141A99BA0<br>**原生等级门槛**：38、40、45、50<br>**实际资源脚本**：CtsErkEureka3Krile1_00512 |

三组原生方法均通过 140B1F610 读取同一个状态+4 字段。首组在剧情 ID5/8/11/14 检查 3/5/13/17；第二组在 21/24/27/31/34 检查 21/23/25/29/35；第三组在 47/54/57/59 检查 38/40/45/50，决定原生姓名牌图标 61721/61722。

三个对应游戏文本表共 100/123/177 行。其实际文案明确写“想要推进下一阶段的剧情，需要将元素等级提升到 n 级。”提取每条文案的原始文本键，并在同事件反编译 Lua 中逐条确认 SystemTalk 调用。去重后的等级集合与各自原生阈值集合完全一致，13 项全部匹配。第一组原始行 27/29 为 3 级、41/43 为 5 级、52/54 为 13 级、63/65 为 17 级；另两组的完整行号、文本键、Lua 调用行号都记录于 client/eureka-elemental-qualification-text-proof.json。

由同一实际事件的原生条件及实际系统提示交叉确认，本字段的准确用途是“优雷卡剧情资格所用元素等级缓存”。这不是宣称找到名为 ElementalLevel 的原生符号，也没有借用另一个 Director 或 ContentKeyValue 的相似字段代替本字段。

## 参数及边界

073B 仅 p1 有效，等价于 073A.p2：140B1F510 将完整 uint32 写到状态+4，相同值不触发刷新，变化才给 140 个对象+9Bh 置 04h。没有 ushort/byte 截断，也没有按本机剧情最高门槛 50 进行 clamp。p2..p8 及 target 不读。它影响剧情资格，不在这个分支直接修改经验、职业等级、区域同步上限或角色战斗属性。

无本类回放，所以不声称网络值与其它“同步后等级”等字段逐次相等。服务器何时发送更新也不由静态文本推定。文本证明的是本字段在这些剧情资格中的等级意义，足以完成 073B 这个单参数类别的客户端定义；073A 仍有 p3 的未命名旗标，因此保持部分确认。

## 可追溯产物

client/eureka-story-level-companions.json 保存真实 holder/vtable/slot；resources-eureka-story-level-customtalk.json 保存完整事件行及脚本名；三份原 luab 及哈希在 client/scripts-eureka-story-level/manifest.json，反编译和反汇编均成功。原始文本表分别在 resources-eureka-anemos-krile-dialogue-raw.json及resources-eureka-pagos-pyros-krile-dialogue-raw.json，逐条调用及阈值集合核对另有机器可读 proof 文件。
