## p1 与 p2 的收尾边界

主分发先把完整 p2 转换为 `p2!=0` 再传入。p2 为 0 时，p1 为 4/6/23 可触发时间轴 164，7 触发 163；其他值没有该专用失败动画。p2 非零跳过这些动画，并只在 p1==3 且本机角色存在时调用相应角色恢复 helper，不走 p2==0 的后续 WarpInfo 回滚分支。

已匹配的预取清理掩码 1048720 包含 p1=4/7/20；卸载条件的机器判断是内部预取状态按 signed32 不大于 2 且不等于 0（正常正值为 1/2，负值也满足），随后重置相关缓存。不能将 signed JG 条件误写成只接受无符号 1/2。p1=5/8 还清理另外的模块状态。p2 为 0 时，WarpInfo 主状态 1/4/5 走 140863170，否则将 p1 保存到+44h 并置+40h 为后续处理。140863170 在主状态 1 且 p1!=3 时直接返回；实际回滚分支会清预取、恢复角色位置/状态并置 WarpInfo 状态 5。

p1 是独立的请求模式。固定 FFCS WarpInfo 的 WarpType 提供 4 Teleport、7 Return 等候选身份，当前失败分支也分别选择相应动画，但尚未完整核对每一种 p1 的发起侧，不因这些已知值就把整个模式枚举计作完成。

额外 p5..p8 和 target 不读；无 02BE 回放样本。本轮增加独立错误正文及精确分支边界，类别保持待查。

证据：140862190 与 140863170 C/ASM、当前主分发 02BE 分支、上述资源文件。PrepareZoning 的 WarpType 另见固定 [FFCS WarpInfo](https://github.com/aers/FFXIVClientStructs/blob/80cb4a7b7e11a6702e2eb8839afd301a918c638e/FFXIVClientStructs/FFXIV/Client/Game/UI/WarpInfo.cs)，它的字段名不自动证明失败包所有数值的业务。
