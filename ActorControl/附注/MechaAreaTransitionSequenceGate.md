# 0DF4 命令 2：跨区完成后的自动序列事件请求门控

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

此前 0DF4 九项子命令及显示／地图标记消费者均已核对，最后保留 event+8280h 的业务缺口。本次从唯一已证直接读者继续向调用时机追溯，给出可检验的客户端用途描述，不冒充官方字段名。

## 发起时机闭合

调用链为 WarpInfo.Update 140860060 → GameMain 收尾通知 140604DE0 → WKSManager 140ECE800 → MechaModule 141A2E3B0。

140860D7E 从 WarpInfo+48h 取 BYTE 到 R8D，140860D83 将已缓存的 WarpType 传 EDX，140860D88 调用 140604DE0；调用后才清 WarpInfo.State 及 Condition45 BetweenAreas。140604DE0 仅在 GameMain 当前内容类型 byte=60 且 WKSManager 存在时转 140ECE800，后者在机甲模块指针+1108h 非空时传同两个参数给 141A2E3B0。因此该读取属于区域转移收尾，先前只写“某处请求序列事件”不足以说明实际时机。

WarpInfo+48h 在区域准备 14085F980 中由 flags.bit3 设置，在区域资料装配 140861B10 中置 1。141A2E3B0 先按传入该 byte 是否非零分支；本字段的读取只在非零分支，不能推广到每次同区域位置移动都触发。

## 字段作用

0DF4 p2 完整 DWORD 等于 2 时，把完整 p3 写 event+8280h，p4..p8 在该子命令不读。它不立即请求事件。

上述区域收尾通知后，要求模块+105C4h.bit0、CurrentEvent 存在、event.Flags.bit1、当前阶段 5/6/7 等门控满足，才读取该 DWORD。值为 0 调用 141A6C2E0，任何非 0 都跳过这次自动请求；不截 low8，不按精确值 1 判断。随后清模块+10h 的一次性标记，字段自身在这里不写回。

因此采用描述性定义：**跨区完成后自动请求机甲角色序列事件的抑制值，0 允许尝试，非 0 抑制**。这比未知 DWORD 更具体，也不假定非 0 表示剧情已经播放、完成次数、领奖、驾驶资格或特定服务器阶段。

## 请求内容和后续边界

141A6C2E0的链已在MechaApplicationClassJob.md 独立证明：使用当前事件 WKSMechaEventData+74h LayoutId、+78h SequentialEvent 行号，先检查单例及两字段有效、同事件尚未活动，再排队请求 14197F760(...,1,11111,null)。当前资源示例 1/8/10 对应序列 330/377/403；同角色未执行请求可能被替换。这里不代表序列已播放，也不保证请求一定成功。

0DF4 整体现在按客户端实际作用、各参数宽度和九项子命令定义闭合；命令 2 采用上述用途定义。未获取服务端字段名或动态样本，这两点没有改成已验证。其它八项、各阶段回调与 Todo显示见MechaProgressDisplayConsumers.md，网络值继续保留完整消费宽度。

原生 C/ASM 证据：140860060（尤其 140860D7E..D88）、140604DE0、140ECE800（140ECE8B4..C6）、141A2E3B0、141A6C2E0、141A6ACC0。包级条件仍要求 WKS 模块加载、事件行匹配、Flags&3==3 及 MassivePcContentDirector 存在；不越过这些门控宣称每个包都会行动。
