# 冒险者铭牌保存应答：0C1E

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

p1 为保存结果，0 成功、非 0 失败；p2 为保存操作类型；p3 为成功时写入的外层 Timestamp；p4 及 Self 额外参数、Target 独立目标未读。

## p2 的可观察含义

| p2 | 内容 |
| --- | --- |
| 0 | **成功 Log**：0<br>**实际文案／行为**：无成功日志；仍可触发一般刷新 |
| 1 | **成功 Log**：5864<br>**实际文案／行为**：所选肖像已应用于冒险者铭牌；使用肖像刷新标记 1 |
| 2 | **成功 Log**：5867<br>**实际文案／行为**：更新了铭牌个人信息；使用一般刷新标记 2 |
| 3 | **成功 Log**：5866<br>**实际文案／行为**：更新了铭牌样式；使用一般刷新标记 2 |
| 4 | **成功 Log**：5868<br>**实际文案／行为**：更新了铭牌可见范围；使用一般刷新标记 2 |
| 5 | **成功 Log**：0<br>**实际文案／行为**：更新搜索备注时补建／重建铭牌资料；无成功日志，使用一般刷新 |
| >=6 | **成功 Log**：不查表<br>**实际文案／行为**：无该成功日志；仍可触发一般刷新 |

原始助手 140BC4320 的汇编将六项 int 表初始化为[0,5864,5867,5866,5868,0]，不是未初始化第 6 项。类型 5 已由下文发起侧确认；类型 0 尚无具名发起点，不凭数组位置命名。

失败时不使用该成功日志表，而以 p1 为数字参数显示 Log5878，实际文案由 SeString 条件决定。相关原文保存于 resources-characard-save-response.json。

## 保存与刷新条件

140C48CB0 在 p1==0 且临时资料首 byte 非零时，将临时块复制到当前块，置 Flags.bit1。Flags.bit2 原本置位则保留当前资料内部 Timestamp，否则该值置 0；再写外层 Timestamp=p3，清临时块，调用助手。成功但临时首 byte 为 0 时没有这条助手通知；失败则清临时块后调用失败通知。

此首 byte 对应资料版本标记，不应沿用此前笼统 HasData 字段名。140DBFA60 仅在 Agent 已激活、Addon 有效、资料条件允许且无更新请求等待时，按 p2==1 设置刷新标记 1，其余 2，然后 RequestCharaCardUpdate 并置等待标志。

## 当前 EXE 与固定 FFCS 的偏移差异

| 字段／操作 | 内容 |
| --- | --- |
| 临时资料块起点 | **当前程序**：+68h，ASM 明确<br>**固定 FFCS**：TempCharaCardData+6Ch |
| 当前资料块起点 | **当前程序**：+128h<br>**固定 FFCS**：+128h |
| 当前资料内部 Data32.Timestamp | **当前程序**：+1B0h<br>**固定 FFCS**：+128h+88h |
| 外层 Timestamp | **当前程序**：+1E4h<br>**固定 FFCS**：+1E4h |
| Flags | **当前程序**：+1E8h<br>**固定 FFCS**：+1E8h |

当前复制指令覆盖 192 bytes，之后重写外层 Timestamp。没有由此强行推导整个 FFCS 结构的 sizeof 都正确，也没有将 6Ch 套入本版临时缓存。p3 在该入口只是原样存入，未据字段名称断言 Unix 秒或其他单位。

本类别现有回放无样本，以上为静态指令、字段和本机文本证据。

## 后续发起侧核对：搜索备注类型 5 及上游 2/3 名称差异

新增发起侧闭环：BannerHelper.SendCharaCardData140BC4210→140C48120 将 reason 原样写内部 448 号 216 字节请求首 DWORD，并缓存 192 字节临时资料。140DBEA80 事件 5 先调用 InfoProxyDetail(10)的 14096EB90 设置 SearchComment(+100h)，再 SendUpdateData；仅 Current 资料 Version=0 或 Data8.Flags bit0（幻想药重置）置位时初始化默认铭牌 Version4 并以 reason5 发送，因此 5 不是单独传送备注文本的包。当前 9 个直接发送调用点均已检查：肖像 1、资料 2、样式 3、可见 4、备注补建 5，没有发现 reason0 直接发起点。固定 FFCS CharaCardDataChangeReason 写 Design=2/Profile=3，与本机成功日志及实际写字段相反：140DC7920 发 2 且更新个人活动时段/资料，140DC6220 及 140DC2E20 发 3 且更新边框背景/装饰；保留当前本机 2 个人信息、3 样式，不直接套上游枚举。

内部 448 是客户端构造器使用的内部消息类型，未将它当作当前线路 opcode。类型 5 发送的是完整铭牌资料；备注本身先由 InfoProxyDetail 另一条路径发送，不能把 0xC1E 回包 p1 起解释成备注内容。类型 0 仍保留待查。
