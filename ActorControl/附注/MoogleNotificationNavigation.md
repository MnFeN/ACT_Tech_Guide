# 0D7F：通知点击后的分类导航与偏移纠正

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

本类别仍保留部分状态，因为 p2 附加 byte 的业务尚不能命名。本轮新增证据确认 p1 不仅控制优先级，还用于指南书分类导航，并纠正了旧 p2 偏移。

## 两个网络 byte 与本地状态不是同一字段

140A58FC7 的通知结构起点为 rsp+20h；140A58FE7 把 p1 低 byte 写 rsp+2Ah，140A58FEF 把 p2 低 byte 写 rsp+30h；140A58FF3 另将 rsp+31h 清 0。因此 p1 在记录+0Ah，p2 在+10h，+11h 是独立本地状态。旧文档+11h 来自 p2 的描述撤回。

## HUD 点击到异步数据完成

140FDD060 处理 HUD 事件 case31，取得 Agent452 后调用 140A59480。后者有队首时将+11h 置 1，调用 140A63570 创建/加载指南书。普通通过其他入口打开时，可先由 140A58A40 清通知队列，不能用这一条入口概括所有点击路径。

资源和数据就绪后的 140A639E0/140A63B60 检查队首+11h，令通知倒计时数组值归 0，用通知+8h 保存的 season 匹配当前可见的两个 season，再读取+0Ah 即 p1。0..3 作为分类索引，>=4 在导航时回退 0，调用 140A5F350(data,seasonIndex,category,0,0)。season 不匹配等失败条件清通知队列。

140A5F350 将 category 存选定 season 记录+1E0h，按该记录+10h 起四个 WORD 中的对应项选择请求。140A65AE0 以同分类查询 CSBonusMissionType，当前行 0..3 的值分别 1..4。这个直接消费者证明 p1 是指南书分类索引；不能继续只写无名优先级 byte，也不能把它当具体任务编号。

队列排序 140A59180 仍以原始 p1byte 比较大小，较大值可前插，未先按导航规则归 0。因此 p1=255 可以有较高排序值，同时导航使用分类 0。显示/排队资格仍受 Agent 当前状态和开放门控，不保证前插或收包后立即打开指南书。

140A58A70 关闭时把队首+11h 清 0，进一步证明这是本地导航状态。当前已核对这些路径没有读取通知+10h 即网络 p2；不据此断言全程序无其他消费者，也不把 p2 猜成目标序号。原 Log1498 达成与 15914 可获得奖励提示、参数截断及不直接发奖的结论保持。
