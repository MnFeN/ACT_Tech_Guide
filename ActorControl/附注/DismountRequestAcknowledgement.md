# 下坐骑请求应答：0393

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

## 修正结论

早期把 p1 命名为“物品动作类别”错误，现予撤回。p1 低 8 位实际是**下坐骑请求序号**。本结论由请求发送、待应答门控、回包匹配及具体失败文案共同核实，不能继续枚举成物品动作类别。

| 参数 | 当前程序行为 |
| --- | --- |
| p1 | 取低 8 位与 UIState+1A3F5 当前请求序号比较；匹配才清序号及+1A3FA 标志 |
| p2 | 完整 uint32 结果；0 跳过失败副作用，1 检查并提示 Permission101 限制，2 显示 Log850；其余非零仍做公共失败清理 |
| p3/p4 | 未读取；Self 额外 p5..p8 及独立 target 同样未读 |

## 发送与匹配

140C4CD40 在普通下坐骑请求时递增+1A3F5 的 byte，溢出为 0 时再加 1，因此生成范围为 1..255；+1A3FA 置 0，调用 GameMain.ExecuteCommand(101,sequence,requestOption,0,0)。140C4CDA0 的飞行落点请求采用同一序号算法，把+1A3FA 置 1，以 ExecuteLocationCommand(101,position,packedRotation,sequence,requestOption,0)发送。

140C4CE30 给出业务身份：查询本机 Mount 行及 MountId，调用 GetIsAirDismountable 和 MoveController.IsFlying，按能否落地发普通或带位置的 101 请求。140BAB640 也按是否飞行二选一调用这两个请求函数。

140C4D4B0 只返回当前序号是否非 0；1406303C0 在状态 3 且没有待应答序号时才继续尝试下坐骑请求。这是待应答门控，不是类别检测。

0393 最后调用 140C4D490：只有 low8(p1)==当前序号，才将序号和位置请求标志一起清 0。不匹配时保留当前状态，避免旧应答清掉新请求。它没有在此处直接创建/卸载坐骑；真实坐骑对象状态由其他包/路径更新。

## 失败副作用与顺序

这些副作用在序号匹配之前执行，所以旧序号或不匹配应答并非完全无作用：

- p2==1：如果路由角色不存在、不是本机，或本机仍有非零 MountId，则调用 140E13AB0(Conditions,101,0)。此函数按 Permission101 规则，在当前不允许的 Condition 中选择优先级最高的一条日志显示。本机已经没有坐骑时跳过这一日志。
- p2==2：Log850“在飞行时，只有处于静止状态并距离地面一定高度以内才能跳下坐骑。”
- 任意 p2!=0：140B819D0 清 EventFramework 相关交互占用字段；相关管理器存在时，140B8D0A0 遍历激活条目并调用 virtual+40h 清理。
- p2==0：跳过以上失败副作用，仍进行序号匹配。这里按实际行为解释，不额外承诺服务器已卸载坐骑或立即完成动作。

收包 140B431D4；请求 140C4CD40/140C4CDA0；普通/飞行选择 140C4CE30 和 140BAB640；pending getter140C4D4B0 及 1406303C0 调用者；回包清理 140C4D490。相关函数 C/ASM及字段候选扫描item-action-current-state-refs.json 保留在 client 目录（扫描文件旧名沿用，不代表最终业务）。文本资源 resources-dismount-request-results.json。
