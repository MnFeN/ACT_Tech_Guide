# 0455：金碟 HUD 阶段的默认分支与宽度

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

0..4及7的窗口与倒计时语义见GoldSaucerReadinessHud.md。本轮补查其他值是否还有专门消费者，并明确收包完整 32 位与内部 16 位缓存的区别。p3..p8 及 target 不读，无回放样本。

## 阶段读取的实际范围

1410A47A0 getter 共有 9 个直接调用点，已逐一核对：

| 调用路径 | 阶段判断 |
| --- | --- |
| 140E6A210/140E6A270 | 非零且相关模式字段为 2 才具备该匹配资格 |
| 140E6A480/140E6A7C0 | 恰为 2 才刷新剩余时间 |
| 140E6B110 | 旧/新阶段比较，用于已确认的附加刷新 |
| 140FD54A0/140FF0E70 | Agent 模式 2 及非零阶段的通用资格 |
| 140FEE780/140FEFEA0 | 1..3 映射 257，4 映射 258，其余 0 |

Agent 实现范围 1410A4000..1410A6200 内，直接访问 Data+F2h 的函数只有 1410A46C0、1410A4700、getter 和 setter：46C0 只按 1/2/3 重开对应窗口，4700 只在 2 刷新确认相关数据，setter 只对 1..4 有专用分支。5、6 等其他值没有对应专用窗口动作；保存在缓存后可继续被通用非零资格判断使用，不能描述为无条件完全无作用。

因此本版的行为可以完整按数值分支定义，不要求替 5/6 编写缺乏证据的服务器事件名。该审计限定为实际 getter 及 Agent 直接读者，不声称穷尽任意未解析间接别名，也不证明所有缓存可容纳的值都是服务端合法阶段。

## 完整 32 位判断与 16 位保存

收包用完整 p1 判断恰 2（保存 p2 截止值）及恰 7（改幻卡匹配模式、p2 选普通/大赛、再按阶段 1 处理）。进入 1410A47C0 后，完整值 0 才调用 Hide；其它值与现有 signed16 阶段作比较、可能初始化 Agent，并按旧阶段 2 清理声音句柄，然后写 low16 至 Data+F2h。1..4 专用动作仍使用完整输入判断。

getter1410A47A0 的 ASM 为 MOVSX word→EAX：阶段先按 signed16 扩展到 32 位，Agent 或数据未就绪返回 0。不能简写成 p1 只读低 16，因为高位仍参与之前的分支。

例如 p1=0x10002 会保存阶段 2，但不以本包 p2 更新截止时间，也不执行 setter 阶段 2 的专用动作；后续按 getter 读取阶段 2 的倒计时路径可使用原有截止值。p1=0x10000 不会走完整输入 0 的 Hide，而是保存缓存 0；p1=0x10001 也不执行完整 1 的专用分支。仅作机器行为边界说明，未声称服务器发送这些值。

p2 在完整 p1=2 时为绝对截止秒，完整 p1=7 时为通常/大赛幻卡匹配布尔，其余输入不读。以上结合已验证的 0..4/7 窗口资源，构成本版收包的阶段控制定义。
