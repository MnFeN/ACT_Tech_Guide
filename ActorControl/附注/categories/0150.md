# 336 / 0x150 WeeklyIntervalUpdateTime

[分类参数](../../README.md#category-0150) · [附注索引](../README.md)

同步下次藏宝图额度与下次挑战笔记重置的绝对时间戳

- 分支地址：`0x140b400a4`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：两个独立时间戳、打包宽度、Unix 秒及小时/分钟消费者已核对。
- 用途：同步下次藏宝图额度与下次挑战笔记重置的绝对时间戳。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | NextMapAllowanceTimestamp 低 32 位，按 Unix 秒解释 |
| p2 | NextMapAllowanceTimestamp 高 32 位，与 p1 合成完整 64 位 |
| p3 | NextChallengeLogResetTimestamp 的 32 位 Unix 秒，零扩展存 64 位 |
| p4 | 此分支未读取 |

说明：140C4D550 写 UIState+19FE0=p1|(uint64(p2)<<32)，+19FE8=uint32(p3)。两字段 getter 已由 FFCS 签名在本机分别匹配 140C4D530/540；GetNext*DateTime 使用 UnixEpoch.AddSeconds。实际消费者 140F58FD0 把挑战重置值与 Framework.GetServerTime 送 1409A98A0，后者差值/3600 和%3600/60 生成小时/分钟；140F5BAF0 同样显示藏宝图额度时间，<=ServerTime+5 时显示可用。请求函数 140C4D4D0 先将两个 64 位字段设-1 并发送内部 cmd1301；回复恢复它们。不是把 p1/p2 作为两个周常时间，也不是 p3 持续时长。p4..p8 未读。

依据：`0x140C4D550`、`FFCS UIState.NextMapAllowanceTimestamp+19FE0 /NextChallengeLogResetTimestamp+19FE8`、`FFCS signatures140C4D530/540;DateTime.UnixEpoch.AddSeconds`、`0x140F58FD0 nextChallengeReset vs Framework.GetServerTime`、`0x1409A98A0 seconds difference /3600 /60`、`0x140F5BAF0 MapAllowance next vsServerTime+5`、`0x140C4D4D0 request cmd1301 and pending=-1`。
