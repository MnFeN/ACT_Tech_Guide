# 211 / 0xD3 ReleaseTemporaryPositionControl

[分类参数](../../README.md#category-00d3) · [附注索引](../README.md)

结束临时位置控制

- 分支地址：`0x140b40cf3`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：临时位置控制原因 bit0、插值门控及公共实例选择关闭已核对。
- 用途：解除路由角色临时位置控制的 bit0 原因，并关闭公共实例选择。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 此路径未读取 |
| p2 | 此路径未读取 |
| p3 | 此路径未读取 |
| p4 | 此路径未读取 |

说明：路由 BattleChara 存在才处理，无网络 p1..8 或独立 target 读取。1408993E0(actor,false,1)计算 GameObject+98h 新值=旧值&FE，先无条件调用角色虚 29(newFlags!=0,oldFlags!=0)，变化才写 byte；不清其他原因位。因为 enable=false，不执行置位路径的 DefaultPosition 快照或虚 28。随后无条件关闭本机 PublicInstance 选择窗口，与 bit0 是否原来已清无关。已追实际消费者 14180B1B0：owner+98h 任意非零时跳过正常向 DefaultPosition/DefaultRotation 修正，清控制器移动工作量并以当前 GetPosition/Rotation 重置插值基准；flags=0 也还需控制器+438h bit40 满足才进入正常插值。因此清 bit0 仅撤销一种临时位置控制原因，其他位非零时不代表解除所有位置控制。140B8B9F0 ProcessInitializeScene 在非本机目标无现有原因位时置 bit0，并登记后续清理；1404EA850/1404EA8E0 界面预览临时把本机移到原点前置 bit0、恢复位置后清 bit0，说明不是单纯物理位置锁或只能由事件剧情使用的位。14090AC70 的定向位移辅助也要求该 byte 全零才调用 MoveController。此包自身不 SetPosition、不恢复到 DefaultPosition、不直接传送；后续行为由相应控制器门控决定。当前没有官方字段名，以真实位置覆盖/插值行为描述，不假造 PositionLock 符号。无回放样本。

依据：`0x1408993E0`、`0x1408993E0 computesold&FE, vf29(newAny,oldAny) beforeconditionalstore`、`0x14180B1B0 owner+98 any→bypass defaultposition/rotation interpolation`、`0x140B8B9F0 ProcessInitializeScene nonlocal actor setsreasonbit0`、`0x1404EA850 /1404EA8E0 preview origin relocation set/restoreclear bit0`、`0x14090AC70 directional displacement requires flags98==0`、`client/object-position-flag-reader-candidates.json 940hits482functions, onlyidentifiedobjectsused`、[TemporaryPositionControlRelease.md](../TemporaryPositionControlRelease.md)。
