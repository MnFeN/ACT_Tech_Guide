# 857 / 0x359 SetPvpSeriesRewardProgress

[分类参数](../../README.md#category-0359) · [附注索引](../README.md)

系列赛等级与领奖进度

- 分支地址：`0x140b3cf9d`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：当前/上一轮已达与已领进度、上游反名及领取失败物品参数已核对。
- 用途：同步 PvP 系列赛已达等级和已领奖进度，或提示领取奖励失败。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 完整 uint32 子命令：0/1 同样写系列赛两项进度；3/4 处理领取失败；2 及其他值仅标记 AgentPvPProfile 刷新 |
| p2 | p1 为 0/1：完整 32 位 0 选当前系列赛，非 0 选上一轮；p1 为 3/4 时只归一布尔转交，最终错误提示函数未读取 |
| p3 | p1 为 0/1：低 8 位已达到的系列赛等级；p1 为 3/4：完整错误码 25（数量上限/背包满）或 28（珍稀重复），其他错误无此日志 |
| p4 | p1 为 0/1：低 8 位已领取奖励的最高等级/领取进度；p1=3 且 p3=25：原始 uint32 物品标识，作为 Log3539 的 Item 表查询参数；其他错误分支不用 |

说明：p2=0 时 p3/p4 分别写 PvPProfile+25h/+26h；p2 非 0 写+2Ah/+2Bh。当前两项与具名 GetSeriesCurrentRank/GetSeriesClaimedRank 及 141081520 界面 AtK 值 7/8 一致。上一轮固定 FFCS 字段/Getter 名称把 2A 称 PreviousSeriesClaimedRank、2B 称 PreviousSeriesRank，但当前本机 141081960 领取按钮用 2B 与当前已领取 26h 作互斥选择，要求请求领取等级==该值+1；141081520 将 2A/2B 与当前已达 25h/已领 26h 成对显示，HasPreviousSeriesRank 亦直接检查 2A 非 0。因此本机语义应为 2A 上一轮已达、2B 上一轮已领；不照搬上游颠倒名称。p1=3,p3=25 显示 Log3539，SeString 为 sheet(Item,lnum1,0)，故 p4 是物品标识而非数量上限数值；p1=4,p3=25 显示背包满 1767；错误 28 显示珍稀重复 1241，p4 不读。无论子命令是否识别，主分支尝试将 Agent135 PvPProfile+0A4h dirtyDWORD 置 1。不会直接发奖励或扣物品；Self p5..p8 和 target 不读。

依据：`0x140C25B40..C40 / LogMessage3539,1767,1241`、`client/pvp-series-rank-accessors.json`、`0x141081520 pairs previous2A/2B withcurrent25/26 UI`、`0x141081960 ASM selects2Bvs26 andcompares requestedRank==claimed+1`、`0x140C25BE0 HasPreviousSeriesRank reads2A!=0`、`resources-pvp-series-reward-status.json`、`resources-pvp-series-reward-status-decoded.json Log3539 sheetItem localnumber1`、`FFCS PvPProfile.cs PreviousSeries2A/2B namesreversed incurrentCNconsumer`。
