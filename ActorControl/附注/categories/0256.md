# 598 / 0x256 SetWeeklyLockout

[分类参数](../../README.md#category-0256) · [附注索引](../README.md)

周常限制状态

- 分支地址：`0x140b437ee`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：周常数值进度、显示消费者与历史四层门槛资源已核对。
- 用途：同步周常锁定状态并关闭大型任务搜索。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 仅低 8 位周常数值进度 V，覆盖 PlayerState+600h；按十进制层数门槛比较而非 bit 图。历史西格玛零式四层门槛 0/10/20/30；保留完整 byte，不自行舍弃个位 |
| p2 | 此路径未读取 |
| p3 | 此路径未读取 |
| p4 | 此路径未读取 |

说明：140BE3100 仅存 byte；主分支若 AgentRaidFinder 已开启，关闭并显示 Log4686 原文进度已经重置。请重新打开窗口。140C2D710 对指定 InstanceContentId 先读行+8A 的 ContentFinderCondition 并要求 CFC+7Bbit5；再读取行+9Ch signedshort 阈值 T。T<0 时输出前三项 false；T>=0 时输出[true, V<T, 10*floor(V/10)>T]，V 为此全局 byte；第四项独立为该副本已完成状态。输出第 3 项被 RaidFinder 显示成 Addon102588 已获得奖励，否则 16469 奖励未领取；招募报名相关路径据第 3 项选择 Log7552 已经获得了招募设定任务的周常奖励，无法申请参加。因此历史编码并非任意 8bit 旗标。当前本机全部 766 行 InstanceContent 中，674 行有非零 CFC 引用且其阈值全部-1；其余阈值 0 的 63 行均无 CFC 引用，另 29 行亦无引用且阈值-1。故当前资源没有同时满足非零 CFC 与非负阈值的行，不能把这段旧资格消费者说成现版本仍实际对某零式层数生效；历史 4.3 资源已补：InstanceContent30063/30064/30065/30066 即 Sigmascape V1..V4.0(Savage)，唯一 signed int16 列 55 分别为 0/10/20/30，与当前算法及界面资格/奖励显示互证。V=10 使第一层奖励已获、第二层已达门槛但奖励未获；V=20/30 相应推进。个位没有单独具名解码，原程序以完整 V 比较资格、以十位比较奖励；不编造个位检查点语义。此跨版本资源映射不等于已用 4.3EXE 动态验证。p2..p8/target 未读。 历史表、来源版本与归一化哈希见 WeeklyProgressHistoricalThresholds.md。外部实现把 255 作特殊全清仅为辅助线索，当前原生没有 255 专门分支。

依据：`0x140BE3100 / FFCS PlayerState.cs`、`0x140C2D710 global142ADF9B8 andsignedInstanceContent+9Ch numericcomparisons`、`0x140F532C0 thirdoutput→Addon102588/16469`、`0x140560B50 thirdoutput→Log7552 reward-lock recruitment`、`resources-instance-weekly-thresholds-raw.json 766rows/674nonzeroCFC allthresholdminus1`、`resources-weekly-progress-gates.json`、`resources-weekly-lockout-ui-status.json`、`sources/InstanceContent-4.3-4cb2931.csv`、`client/weekly-progress-historical-thresholds.json upstreamBlob7c4a36c`、[WeeklyProgressHistoricalThresholds.md](../WeeklyProgressHistoricalThresholds.md)。
