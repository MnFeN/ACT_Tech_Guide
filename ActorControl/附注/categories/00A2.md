# 162 / 0xA2 SetWeddingQuestFlags

[分类参数](../../README.md#category-00a2) · [附注索引](../README.md)

永结同心资格状态

- 分支地址：`0x140b42e17`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：永结同心方案及任务门控已核对；两位完整业务名称待查。
- 用途：设置永结同心方案及任务资格相关的两个旗标之一。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 完整 signed int32 位索引；仅 signed<2 检查。正常 0/1 分别选 01h/02h；负数也进入，BTS/BTR 寄存器索引按 low5 取位后只保存 low8，故-32/-31 等可改正常位，-30..-25 可改 byte 其他位，不能概括负数均无效 |
| p2 | 完整 uint32 恰等于 1 才置位，其余值清位。主入口 140B42E03 先 cmp DWORD [rsp+78h],1，setz R8B；setter 比较收到的 0/1，不是直接截原网络低 8 位 |
| p3 | 此分支未读取 |
| p4 | 此分支未读取 |

说明：PlayerState+5FEh 即 byte142ADF9B6。原生 Lua GetWeddingPlan→140B9B770→140B9B650：角色未接受短 QuestId1578 且 bit1 置位时直接返回方案 1，否则从永结同心 QuestHandler 求方案。GetWeddingEquipmentCatalogIds 也按此方案选择目录。140B9BA30 对本机角色返回 bit0 未置；Quest 资格 140E04C30 在 QuestId1578 门控区失败置 1000000000h。不能把 bit0 直接命名已婚或把 bit1 直接命名白金方案；原生只证明上述条件。未识别为函数的 140B9BB10 亦按参数查询同 byte 任意位，仅本机有效。p3–p8 未读。 新核对 ASM140BE2792/279C 为 bts/btr eax,edx（寄存器目的），位索引使用 low5；写回只 mov byte。例 p1=-30、p2 完整 32 位==1 会置 byte bit2，p1=-1 选择 bit31 但写回 AL 不改变原 byte。该异常输入边界不证明服务器会发送负数，也不给未具名 bit2..7 编业务名。Quest 资格掩码读者扩大审计没有找到可独立命名 bit0 的拒绝文案，仍保留既有业务不确定性。 修正此前低 8 位等价说明：主入口 140B42E03 的机器字节 83 7C 24 78 01 为 DWORD 比较，140B42E13 SETZ R8B 传 setter。内部 140BE278C 虽 cmp R8B,1，但网络值已经完整比较归一；p2=257 实际清位，不能与 1 等价。见 WeddingNetworkBooleanWidthCorrection.md。p1 负索引边界仍不变。
