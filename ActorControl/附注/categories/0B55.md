# 2901 / 0xB55 SetFieldRecordItems

[分类参数](../../README.md#category-0b55) · [附注索引](../README.md)

批量战果记录登记

- 分支地址：`0x140b455f4`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：已核对。
- 用途：同步战果记录道具登记缓存并标记响应已加载。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | mask1：bits0..31 映射缓存索引 0..31；当前索引 1..31 有战果记录道具映射 |
| p2 | mask2：bits0..22 映射缓存索引 32..54；当前索引 32..50 有道具映射，高 9 位不影响结果 |
| p3 | 入口读取并转交 mask3，但当前宽度 32、仅展开 55 项，实际不选择其中任何位 |
| p4 | 入口读取并转交 mask4，但当前宽度 32、仅展开 55 项，实际不选择其中任何位 |

额外参数：Self p5–p8 及 Target 独立 target 未读。

说明：140C4E010 先解引用四个 mask 传 140C47440；构造固定每组 32 位，后者只展开 55 个 bool，索引 i 的来源为 mask[i/32]的 bit(i%32)，所以当前 p3/p4 没有语义效果。撤回原“4mask 都参与”的描述。随后 140C4E040 仅在 map 类型键 19743 已存在时设状态 2。140C471E0 在状态 0 发命令 3100 查询并设 1 等待，状态 1 返回 3；状态 2 后按 ItemAction.Data0 布尔返回已登记 1 或未登记 2。该包完成的是道具是否已登记的查询缓存，与 0A28 直接通知记录界面属于不同存储。

依据：`0x140C4E010 / 0x140C47440 expansion55 / 0x140C4E040 map19743=2`、`0x140C47070 ctor width32 and bool55`、`0x140C47130 map keys19743 and50454`、`0x140C471E0 ItemAction type19743 checks Data0 registration bool`、`resources-itemaction-type19743.json / resources-itemaction19743-linked-items.json`、[FieldRecordRegistrationFlags.md](../FieldRecordRegistrationFlags.md)。
