## 参数与行为

- 核对状态：阶段 0..4/7、其他值的保存/通用资格及 16 位缓存边界已核对。
- 用途：金碟内容 HUD 阶段子协议。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 完整 32 位 HUD 阶段先参与分支：0 隐藏，1 等待正文，2 参与确认，3 准备人数，4 关闭准备窗口；7 设置幻卡模式 2 后改以 1 交给 setter。其余非 0 值保存 low16 至 AgentData+F2h，无专用阶段动作；getter 按 signed16 扩至 32 位，详见专题 |
| p2 | p1==2：与 GetServerTime 低 32 位同一基准的绝对截止秒数，显示 max(截止时间-当前时间,0)；p1==7：非零选择幻卡大赛匹配，0 通常匹配；其他阶段未读 |
| p3 | 此路径未读取 |
| p4 | 此路径未读取 |

说明：默认链 140E6B110 将阶段 2 的 p2 缓存 handler+68h，随后 140E6A7C0 只在 HUD 阶段 2 时按 uint32 与 GetServerTime 比较并计算剩余秒；每帧 140E6AF80 继续刷新。1410A4A30 写 NumberArray81[1]，格式化秒数至 StringArray76[0]，由 Confirm/Status 界面显示，因此 p2 不是剩余毫秒或泛未知状态。阶段 3 准备人数另由 0456 同步。阶段 7 设置 Agent 模式 2，并将准备人数设 1/2；p2!=0 选择 Addon9549 幻卡对局室大赛对局，否则 9528 通常对局。离开阶段 2 的 1410A5530 处理此前 PlaySoundEffect74 取得的两句柄，虚调用+288 传 500 后清句柄，不应写成停止比赛计时。5/6 及其他没有专用分支的阶段值仍写入 phase，但完整服务器事件名称未证明。p3/p4 及额外参数未读。 后续补查 getter1410A47A0 的全部 9 个直接 call：140E6A210/270 及 140FD54A0/FF0E70 仅按非零和模式条件判断匹配资格；140FEE780/FEFEA0 只对 1..3 返回 257、4 返回 258，其余 0；倒计时仍仅 phase2；未发现 5/6 专用动作。Agent 代码范围内直接 F2h 读取另有 1410A46C0 仅重开 1/2/3 窗口、1410A4700 仅 phase2 刷新确认，setter 本身仅 1..4 有专门分支。故其他阶段值以原编号、保存及通用非零资格描述即可，不要求为无专用分支虚构服务器事件名。新核实 ASM：setter 低 16 保存，getter MOVSX word→EAX；收包及 setter 专用动作按完整 32 位比较。例 p1=10002h 写缓存 2 但不采用本包 p2 作新截止值且不走专用阶段 2 动作，之后倒计时 getter 可读到 2；不能把 p1 先截 16 后解释全部逻辑。无回放样本，未证明异常高位输入为服务端合法值。
