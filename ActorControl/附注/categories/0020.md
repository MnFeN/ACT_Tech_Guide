# 32 / 0x20 SetDying

[分类参数](../../README.md#category-0020) · [附注索引](../README.md)

濒危状态开关

- 分支地址：`0x140b3a818`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：具名 IsDying、跪地姿态、任务判定和参数范围已核对。
- 用途：切换角色 Dying 濒危状态，控制跪地姿态、任务敌人判定及任务物品使用资格。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 全 32 位按非零/零设置或清除 Character.ActorControlFlags+1CE8h 的 0x40 位；设置时按角色 EventId 通知 EventHandler 虚 79 |
| p2 | 此分支未读取 |
| p3 | 此分支未读取 |
| p4 | 此分支未读取 |

说明：路由角色必须有效。p1 非零 OR0x40 并通知 EventFramework；p1=0 清位，不发同一通知；p2..p8 及 target 未读。原生 140B90470 明确注册角色 Lua 方法 IsDying→140B90370，后者解析角色包装后读取同一 7400(1CE8h)偏移 0x40 位，故业务可定名 Dying，不能解释为 HP=0 或角色死亡。1408BEA90/1408C0BB0 默认姿态优先选择 ActionTimeline37 event_base/event_base_knee_suffering，更高优先 730 字段仍可覆盖。140C22700 统计 7 个关联战斗对象时排除该位，140DFA140/2C0 任务侧敌人存在判定亦要求此位为 0。当前 18 份 Quest 脚本包含 IsDying；如 AktKza012_04191.IsEventItemUsable 要求敌人布局/物品、使用权及归属符合后，还必须 IsDying，否则设置 LOG_MSG_CANT_USE_ITEM_ENEMY_IS_NOT_DYING 并返回 false。这说明是任务敌人打至濒危后使用指定物品的资格，不是任何物品都可用。直接字段扫描 127 处归 78 函数，动态 CL 测试经 C 核对仍为 bit0，未发现直接全攻击取消调用；不把 FFCS 注释 All attacks will be cancelled 扩写为该客户端收包的已证额外行为。当前无此类回放样本，确认范围为当前客户端收包、具名查询和上述消费者。
