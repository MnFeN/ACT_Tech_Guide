# 321 / 0x141 SetFishingRecord

[分类参数](../../README.md#category-0141) · [附注索引](../README.md)

钓鱼尺寸纪录

- 分支地址：`0x140b3fd76`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：44 个纪录分组、钓鱼/刺鱼双表、尺寸评级和 0.1 星寸显示消费者已核对。
- 用途：同步 FishingRecordType 分组的最大尺寸鱼种与尺寸纪录。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | uint32 纪录分组索引，对应 FishingRecordType 行号；读者 44 槽(0..43)，本收包入口无边界检查 |
| p2 | 低 16 位纪录鱼种：非 0 且<20000 查 FishParameter 行，>=20000 查 SpearfishingItem 行；不是 Item 行号 |
| p3 | 低 16 位纪录尺寸，单位 0.1 星寸；UI 用值/10 和值%10 格式化 |
| p4 | 此路径未读取 |

说明：写 UIState+0D7C+2*index 和+0DD4+2*index。140BF4660/5040 按 44 槽读取鱼种，sheet247 FishParameter 和 610 SpearfishingItem 分开异步加载；140BF4C80/4DD0 把 p3 缓存作为尺寸并与 FishingRecordType 五档尺寸阈值比较生成评级。缓存槽号存记录+14(hex)，Event8 回调 140F76EF0 将记录复制到 FishRecord Agent，最终 140F784E0 以槽号查 FishingRecordType 并用 Addon3809 显示尺寸，明确为十分之一星寸。空鱼种槽不加载。收包本身直接覆盖记录，不比较新旧值；“最大尺寸”指纪录界面的业务，不声称客户端在此计算 max。p4..p8 未读。

依据：`0x140B386F0`、`0x140BF5040 ASM EDX247 and0x140BF5200 EDX610`、`0x140BF4C80/4DD0 size thresholds ofFishingRecordType;44slots`、`0x140F76EF0 Event8 cache→AgentFishRecord copy`、`0x140F784E0 Addon3809 size/10 size%10`、`resources-fishing-record-labels.json FishingRecordType andAddon3809`。
