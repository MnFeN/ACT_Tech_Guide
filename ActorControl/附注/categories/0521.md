# 1313 / 0x521 VerminionSummonResponse

[分类参数](../../README.md#category-0521) · [附注索引](../README.md)

萌宠召唤队列应答

- 分支地址：`0x140b3909c`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：已核对。
- 用途：确认萌宠之王召唤队列项，并同步召唤等待及已用召唤点。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 完整 32 位类型；恰 1 时使用 p3 计时且在 p2 非 0 时移除队首并通知队列项动画；其他值仍更新 p4 并处理请求锁 |
| p2 | 完整 32 位确认值；0 不推进队列。非 0 且 p1=1 时同时作为已确认队列项编号通知 LovmQueueList，匹配界面缓存的 byte 队列序号，非通用结果码/CompanionId |
| p3 | 仅 p1 恰 1：uint32 百分之一秒的召唤等待，除 100 转 float 秒，无论 p2 为 0 或非 0 均覆盖+65Ch 剩余和+660h 初始等待 |
| p4 | 低 8 位当前已用召唤点，覆盖 Director+6B9h；参与后续 Companion.Cost 累计与可召数量判断，非本次消耗差值 |

说明：140E79AB0 先按 p1=1 写计时，再无条件写 p4 低 8。p2 非 0 且类型 1：队列 8byte 记录左移一项、数量非 0 才减 1，重算可召数量，Agent206 以类型 1 透传 p2。1410CE020 将其作为[3,p2]发送 Agent+44h；1410CE810 创建 Addon428 LovmQueueList 并将 ID 存此字段。注册 14010A910→creator140134890→ctor1416DB010 确认 vtable1422C60C8；虚函数 51 经 1416DB630→1416DB650 处理命令 3，以完整 p2 逐项匹配 byte 缓存+278h+n*48h，命中时拷该项图标到离队表现节点并播放时间轴。缓存身份由 1410D0F20 将队列记录 byte0 写 NumberArray100[103+3*n]，1416DBF90 读回，独立证明编号用途。本地队列 140E77DF0 由+6B6h 循环序号生成 byte0，FF 后回 1，零保留；不是 CompanionId/EntityId/全局顺序号。原生 p2 只非 0 门控，异常非 byte 值仍可能推进队首但无法匹配动画，不声称入口校验。p2 非 0 无论类型均清+6B7h/6B8h；p2=0 仅清+6B7h。未对 p1 其他值擅造操作名或将零定义为具体失败原因。p5..p8 及 target 未读，无回放样本。 栈帧修复后的 140E73E30 发送侧已直接核实：ExecuteCommand2008 依次发送队首 CompanionId、记录 byte1 门索引、byte0 队列序号，服务器随后经 0521 确认此序号。

依据：`0x140E79AB0 timing/cost/queue mutation`、`0x1410CE020 [3,p2] toAgent+44`、`0x1410CE810 OpenAddon428 ->Agent+44`、`0x14010A910 creator428 registration`、`0x140134890 ->0x1416DB010 vtable1422C60C8`、`0x1416DB630/1416DB650 command3 full32 comparebytequeueid`、`0x1410D0F20 NumberArray100[103+3*n]`、`0x1416DBF90 queueUIbyte identity`、`0x140E77DF0 localqueue rotatingbyte id`、[VerminionQueueAcknowledgement.md](../VerminionQueueAcknowledgement.md)、`0x140E73E30 ExecuteCommand2008 param3=queuebyte0`。
