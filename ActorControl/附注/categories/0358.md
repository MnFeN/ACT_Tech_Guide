# 856 / 0x358 SetRespawnState

[分类参数](../../README.md#category-0358) · [附注索引](../README.md)

复活倒计时与战章变化

- 分支地址：`0x140b3cb15`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：已核对。
- 用途：同步角色复活剩余倒计时、允许复活阈值及 Feast 战章变化。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 角色 EntityId；等于本机 sourceId 时更新本机 Revive，观战路径按此 ID 匹配角色记录 |
| p2 | uint32 以 0.1 逻辑秒单位编码剩余复活倒计时，转 float 乘 0.1 后写 Revive+18h；每逻辑帧递减至 0 |
| p3 | uint32 以 0.1 逻辑秒单位编码允许复活的剩余时间阈值，转 float 乘 0.1 后写 Revive+1Ch；剩余倒计时<=此阈值才允许从 Dying 进入 Revivable（另有至少 3 秒及角色状态条件） |
| p4 | Feast 掉落前战章持有数，写 Revive+20h；对应 Addon5409 lnum1 |

额外参数：Self p5 为 Feast 掉落后战章持有数，写 Revive+24h，对应 Addon5409 lnum2；观战更新只消费 p1–p3。p6–p8 及 Target 独立 target 未读。

说明：实例 142ADFCE0=UIState+1360h，固定 FFCS 明确为 Revive，撤回笼统 PvP 管理器命名。140C0ED10 每帧对+18h 减 FrameDeltaTime*GameSpeedMultiplier 并钳 0；Dying 阶段要求死亡经过至少 3 秒及其他角色状态条件，且 remaining==0 或+1Ch>=remaining 才设 Revivable。140C0E880 及 0ED10 的死亡界面模式 6/8 取 ceil(remaining)传 AgentRevive，Feast 路径额外将+20/+24 填 Addon5409“战章持有数：旧→新”；通常 PvP 文案 Addon4747 为一定时间后返回己方阵营。p4/p5 不参与计时。观战 141A3E7A0 将两个缩放 float 写 312-byte 匹配实体记录+304/+308，再由外层请求刷新。关键符号以汇编为准：140B3CB17/34 mov eax 清高位，CB2F/38 cvtsi2ss xmm1/2,rax，故 p2/p3 均为 uint32 而非当前伪码 signed。

依据：`0x140B3CB17..41 uint32 numeric conversions`、`0x140C0F4D0 stores`、`FFCS UIState.cs +1360 Revive / Revive.cs +18/+1C/+20/+24`、`0x140C0ED10 countdown and Revivable gate`、`0x140C0E880 ceil countdown and Addon5409 medals`、`0x141A3E7A0 spectator entity record`、`resources-revive-countdown-medals.json raw SeString`、[ReviveCountdownAndMedals.md](../ReviveCountdownAndMedals.md)、[FloatConversionAudit.md](../FloatConversionAudit.md)。
