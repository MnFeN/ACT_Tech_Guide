# 1306 / 0x51A SetVerminionMinionResources

[分类参数](../../README.md#category-051a) · [附注索引](../README.md)

萌宠生命值与特殊技蓄力

- 分支地址：`0x140b3909c`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：已核对。
- 用途：同步萌宠之王宠物生命值与特殊技蓄力，并更新就绪标志。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 阵营/侧索引，计算 side*24 参与槽定位；当前入口没有检查范围 |
| p2 | 该侧宠物槽索引，每侧布局 24 槽、stride20；当前入口没有检查范围 |
| p3 | 完整 32 位当前 Health 原值，同时写 Director 槽与可找到实体的 CharacterData.Health，无 clamp |
| p4 | 完整 32 位 MaxHealth 原值，同时写 Director 槽与实体 CharacterData.MaxHealth，无 clamp |

额外参数：Self p5 为当前特殊技蓄力/SP 的 32 位数值；signed>=Companion.SkillCost 时置就绪 byte，并原样写显示记录；p6..p8 未读

说明：140E77710 以槽 Companion 行号查资源，row+2Dh 准确对应 SkillCost（typed Companion1=30、47=20，raw 列 offset45 互证）。Self p5 是当前特殊技蓄力/SP 数值，按 signed int32 与该 ubyte 阈值比较；0x140E7776E cmp r15d,ecx /77771 setnl 证明确为 signed>=，高 bit 不是无符号大数就绪。将比较结果写槽+2 就绪 byte。随后按槽 EntityId 查角色，存在时写 Health/MaxHealth，再按 ObjectIndex>>1 索引 Director 的 12-byte 显示记录，把 p5 原始 DWORD 与 SkillCost 阈值分别写+EB4/+EB8；实体不存在仍已更新槽生命和就绪 byte。p6..p8 与独立 target 未读。现有回放无样本，未动态召唤/施放。

依据：`0x140E77710 exactslotlayout andlife/SPwrites`、`0x140E7776A..77774 SkillCost andsignedsetnl`、`resources-vermiminion-state-candidates.json typedCompanion1 SkillCost30`、`resources-verminion-special-minion.json Companion47 SkillCost20`、`resources-verminion-companion-columns.json offset45`、[VerminionHealthAndSkillPoints.md](../VerminionHealthAndSkillPoints.md)。
