# 1304 / 0x518 SetVerminionFacility

[分类参数](../../README.md#category-0518) · [附注索引](../README.md)

萌宠之王设施状态

- 分支地址：`0x140b3909c`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：已核对。
- 用途：同步萌宠之王设施的启停、位置特效及剩余强度。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 完整 32 位子命令：0 停用/破坏，1 播放设施位置 LOVM 特效，2 激活/重启，3 覆盖设施剩余强度；其他值本分支不处理 |
| p2 | 侧索引，正常 0/1，与 Director+631h 本方侧比较决定己方/敌方表现；入口无范围验证 |
| p3 | 该侧设施索引 0..7：0..2 萌宠之门 A/B/C、3..5 奥秘核石 A/B/C、6 探索眼、7 防御盾；入口无范围验证 |
| p4 | 命令 1：完整 32 位专用 vfx/lovm/eff 编号，恰 100 比例 1，其他比例 2；命令 3：完整 32 位设施剩余强度原值覆盖（奥秘核石 HUD 按/5000 绘制）；命令 0/2 不读 |

说明：各侧 8 项、记录 stride48，active+0、LayoutId+8、当前强度+0C、坐标+10、受击提示冷却 float+20。命令 0/2 先写 active0/1，即使 Layout 查找失败也留存；有 Layout 则按本方/敌方播放 3/7 或 1/5，并显示设施提示。帮助 2194 明确门/眼/盾破坏后重启、奥秘核石不重启，不能把命令 2 对每种设施都笼统描述成复活；原生仍允许写其 active 且核石分支沿用 4830/31 提示。命令 3 无 clamp 写缓存，找到匹配 LayoutId 对象再写 Character+1B4h（通用 Mana）；不能称普通玩家 MP。独立 140E791F0 原样返回缓存，Agent1410D1650 按己/敌核石 3..5 转 NumberArray98[6..8]/[9..11]，_LovmHeader1416D6E60 读这些值，1416D7440 以/5000.0 画每条宽度，1416D6E60 还按 1000/2000/3000/4000 阈值分档表现；初始化 140E75C00 赋核石 5000、其他设施 1000。这确认是设施剩余强度原值而非 0..100 百分比或扣减差值，5000/1000 是当前初始显示基准，不是入口校验。核石新值按 signed32 小于旧值且 2 秒冷却结束时播 LOVM103，并置冷却 2.0；逐帧 140E73E30 以 FrameDeltaTime 递减。命令 1 位置取 Layout，不取 ActorControl 浮点坐标；LOVM 编号非通用 VFX 表行。p5..p8 及 target 未读，无回放样本。

依据：`0x140E78D30/78C80/78FC0/790C0 percommand`、`0x140E75C00 initial1000/5000`、`0x140E791F0 directfacilityvalue getter`、`0x1410D1650 NumberArray98[6..11]`、`0x14010A910 Addon425 primarycreator140134670`、`0x140134670 _LovmHeader ->1416D6680 vtable1422C5728`、`0x1416D6E60 thresholddisplay /1416D7440 barvalue/5000`、`0x140E73E30 2secondimpactcooldown update`、`resources-verminion-facility-help.json`、[VerminionFacilityStateAndStrength.md](../VerminionFacilityStateAndStrength.md)。
