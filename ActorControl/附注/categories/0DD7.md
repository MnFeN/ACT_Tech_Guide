## 参数与行为

- 核对状态：计时目标耗时秒数已核对；其他目标类型及评级 4 业务名待查。
- 用途：宇宙任务：更新任务评级及关联结果值。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | 32 位 MissionRank：固定 FFCS0 无、1 铜、2 银、3 金、5 失败；当前原生另有 4 分支使阶段进度显示 100%，其业务名仍待确认 |
| p2 | 计时目标 MissionType8：已用秒数，写 WKSManager+EB0h；结果界面用 max(MissionTime-p2,0)还原剩余秒数；其他类型未见该 UI 读取，不强行套此语义 |

| p4 | 本消费者未读取 |

说明：140A78150 AgentWKSMissionInfomation 消费者证明 p2 用途：在完成相关刷新标志或 manager+EB8h 置位、且当前 WKSMissionToDo.MissionType==8 时，取+EB0h，按资源 MissionTime 秒数减该值并钳 0，供剩余时间显示。资源 SilverStarRequirement/GoldStarRequirement 分别除 10 转为秒，Addon16792 明确“剩余时间 m:ss 以上”。例如 Unit363 时限 600 秒、银 492 秒、金 502 秒；若 p2=100 则结果剩余 500 秒，银门槛满足而金未满足。这里是静态代入例，不是回放实测。非结束阶段取 deadline-GetServerTime。原笼统 p2 未知已缩小为计时目标耗时，未宣称所有任务类型同义。完成第一次评级/后续评级变化分别设置 UI 刷新类型 2/4；金牌还更新任务物品待处理状态等。 新增 E90h 精确位移全.text 扫描 51 处、32 个函数候选。验证属于 WKSManager 基址的读者后，只有 141A73E60 对 rank4 作专门 100%进度分支；140148C10 只把 rank1/2/3 归入奖牌通知，不含 4；其他资格/结果 UI 多仅测试 rank 是否非 0。阶段结束/无奖牌完成是候选解释，未有独立文本或发起证据，不提升为已证枚举名。扫描中许多同偏移属于无关结构，未计为 WKS 读者。 对结果值 EB0h 新增跨宽度补查：按已解码操作数覆盖 EB0..EB3（含 EA1..EB3 起点的候选读写）检索 80 处/53 函数，全部成功反编译；原清单保存，不将相同位移自动视为同一 manager。已核实 WKS 语义路径仍是 140A78150 在 MissionType8 的读取、141A709C0 及 141A74C00 写入；另 140ECFED0 清理 manager 时将 EB0h 起 qword 清 0。新扫描覆盖了按较早偏移宽读取的遗漏可能，但尚无新证据给其他目标类型参数或 rank4 正式业务名补名，故继续部分确认。
