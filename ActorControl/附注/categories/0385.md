- 分支地址：`0x140b422a5`。
- 回放观察：0 次；包族 {}。

## 参数与行为

- 核对状态：弹药槽可用性及逐技能 Bullet 映射已核对；byte 数量单位待查。
- 用途：更新炮台弹药槽的可用值，影响炮台技能能否发射。

| 参数 | 读取与语义 |
| --- | --- |
| p1 | unsigned32 槽索引 0..3；其余不写 |
| p2 | 低 8 位覆盖 ActionManager+11Ch+p1；0 表示该槽无可用弹药，非 0 通过相应弹药资格检查；是否精确剩余数量尚未证明 |
| p3 | 此路径未读取 |
| p4 | 此路径未读取 |

说明：要求路由 BattleChara 存在，但写的是全局 ActionManager，并非路由角色私有数组。1408E8960 GetActionStatus 在角色模式 8 时匹配 Ballista 前 3 个 Action，按对应行+0Ch/+0Dh/+0Eh 选 Bullet 模式：1 不读槽数组直接通过此项检查；2 四槽任意非零即通过；4/5/6/7 分别查 slot0/1/2/3；0/3 及其他值拒绝。选中槽为 0 或模式 2 四槽全 0 返回 LogMessage652“无法使用，弹匣中没有弹药了。”。这里只证明资格，不把非零 byte 当成自然数量。1408F1A90 初始化一次复制四槽，0385 逐槽覆盖；p3–p8 未读。Lumina 只命名第一 Bullet 列，另外两列虽显示 Unknown0/Unknown1，原生确实按每个 Action 索引分别读取。 进一步全.text 检索 byte 寻址+11Ch/+11Dh/+11Eh/+11Fh，共 193 处、85 个函数，保存 ballista-ammo-reader-candidates.json 及独立候选伪码。相同偏移命中包含配置 byte 数组、各独立类的状态位等，不能视为同一 ActionManager。已识别 ActionManager 消费者仍为 GetActionStatus 的零/非零资格检查，未找到可证明此 byte 自然数量单位的显示/递减证据；此扫描不覆盖基址先调整、非 byte 整组拷贝、非显式位移等形式，不能据此证明其他消费者绝不存在。 较宽访问与对象参数转发补查见 BallistaPackedAndArgumentFlowAudit.md：326 绑定 566 调用边内识别 1408E7D70 在+11Ch 整组清零；这是复位证据，不证明数量单位。保留 14 个反编译/原型缺口和动态索引/别名覆盖边界。 后续五个栈帧已重建并全部恢复反编译，重新参数流 329 绑定 599 边，固定字段证据仍为初始化和复位；原 326/566 输出另存 before-frame-repair 版本，业务单位仍待查。 新增 ActionManager 对象 Microcode 局部别名追踪：带常量 1600 组合批次达到上限、剩 13251 组合；另仅跨调用传指针标签的 354 组合/353 函数批次在修复 2frame 后无错误/超限/队列，目标读者仍只有已知 GetActionStatus 的零/非零判断。后批不传播调用者常量，不构成前批完成或全别名穷尽。见 BallistaMicrocodeAliasAudit.md。 后续 m_stx 地址寄存器标签问题已修复并重跑相关批次，按目标实际读取站点比对无新增/移除；见 MicrocodeStoreAddressFix.md。
