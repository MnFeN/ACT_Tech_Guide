# 0DF8：按 PopRange 生成组批量退场

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

| 参数 | 实际语义 |
| --- | --- |
| p1 | 完整机甲事件行号，事件外层和场景各自核对 |
| p2 | low8 子命令 3 或 4 |
| p3 | 子命令 3 的 PopRange 布局 InstanceId/生成组键；4 不读其值作筛选 |
| p4 | 子命令 3 处理上限，完整 uint，0 提前返回；4 使用内部已生成数 |

外层还要求事件 Flags&3==3、模块存在；p5..p8 及 target 未用，7 阶段虚 9 无附加消费者。

## 生成组键的独立来源

141C57470 按 LayoutWorld.GetLayoutInstanceStatic(40,payload+8,0)取生成范围，实例类型 40 由固定 FFCS 明确为 PopRange。该函数将 payload+4 的 EObj BaseId 写动态记录+0，将同一 payload+8 写记录+4，并从 PopRange 候选位置生成记录。0DF8 比较的正是记录+4，因此 p3 不是 EObj 行号、角色 EntityId 或泛指对象类型，而是 PopRange 生成组键。

## 子命令 3：排序后从远到近

p4 为 0 时在排序前直接返回。否则 141C5BD30 使用 141C5B750 比较器，按 source 位置到记录 XYZ 的三维欧氏距离升序；实际处理再从 vector 尾部逆序，故从远到近。相等距离不承诺稳定顺序。

比较器还有副作用：被比较记录的 EObj BaseId 不是 2015375，且距 source 严格大于 WKSParam1006（当前 80）时，置记录+CC 清理标志；等于 80 不因这条规则置位，已置位也不清。因此排序可能给不属于 p3 组的记录额外标记清理。不能将其视为完全纯排序，更不能声称只会影响筛选组。单项 vector 不需要比较，也不能凭该规则说每项都必经一次距离判断。

## 子命令 4：内部计数

不重新排序、不按 p3 筛选，沿当前 vector 尾部逆序，以上次状态中的已生成数 scene+6238 作为处理计数。p4 不参与。内部计数为 0 时没有入口提前返回；若先遇到有效但尚未生成（index<0）记录，仍标记并减计数，DWORD 可回绕。保留实际边界，不擅自把它修成“零必定不处理”。

## 什么会消耗处理计数

只有 BaseId 和组键均非 0 的记录进入主体；命令 3 还需组键匹配。先置+CC，然后：index<0 直接减处理计数；index>=0 且能查到 ReactionEventObject 时，启动目标 30 的退场计时、置+CE，再减计数。index>=0 但对象查不到时，已经标记+CC 却不消耗计数。故参数上限不能简单等同最终实际销毁数量。

这里不检查旧+CC/+CE 来跳过重复目标，重复包可重启已存在对象的退场计时。与 E01 强制清理路径的“未标记才开始计时”不同。

30 单位时间由 FrameDelta*GameSpeed*30 推进，名义约 1 秒。后续 141C57B20 等待计时结束、销毁对象、清记录及关联，并按生成组发送 internal3476 回报；详见 MechaReactionObjectShutdown.md。收包本身没有立即删除所有对象。

## low8 的汇编核对

旧 C 伪码有 v17=p2 随后与 4 比较的表达式，容易误读成完整 DWORD。ASM141C542FF 先 movzx r14d,bpl，141C54390 再 cmp r14b,4，实际两处均按 low8。因此 p2=260 与 4 走同样不筛组分支，不能把它当成新的完整值模式。

没有对应回放样本。生成键、排序方向、副作用、上限消费及延后回收均已核对，转为已核对。
