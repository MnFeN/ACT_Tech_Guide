# 战果记录登记的两份状态：0A28／0B54／0B55

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

0B54／0B55 的 UIState+19F78h 模块用于 ItemAction.Type19743 的登记查询。当前 50 个该类型 ItemAction 均关联“战果记录：…”道具，Data0 为 1..50。140C471E0 以 Data0 直接索引模块+Ch 的 bool；这条消费链明确了业务，不再笼统称未知 UI 布尔模块。19743 是 ItemAction.Type，而不是 ItemAction 表行号。

## 单项 0B54

p1 为 group，p2 只取最低的置位 bit，索引=group*32+bit；p3 完整 32 位恰等于 1 写 true，其他 false。p4 及额外参数未读。多 bit 只更新一项，不能称批量 mask。

构造 140C47070 将位宽+8 设 32，初始化+Ch 起 55 个 bool。当前 Data0 有效值 1..50，缓存 0 与 51..54 无对应道具。入口没有边界检查；p2==0 时会扫描 32 次，随后写 group*32+32，也就是下一组首项，而非直接返回。此边界行为是当前代码事实，不表示合法服务器一定会发送零 mask。

## 批量 0B55

140C4E010 解引用四个参数并转交 140C47440，但后者只展开 55 项，构造又固定宽度 32，因此结果仅由 p1 全部 32bits 和 p2 低 23bits 决定。p3／p4 确实被读入寄存器／临时数组，但当前循环永不选择第 3／4 个 mask，它们不影响最终状态。不能把“参数被读取”混同“每个参数都控制有效记录”。

之后只在类型 19743 状态 map 已有键时，将状态置 2。140C47130 初始化该 map 时加入 19743 和 50454 两种类型。道具检查 140C471E0 在 19743 状态 0 时发送命令 3100 并设 1，状态 1 返回等待值 3；收到 0B55 置 2 后，按登记 bool 返回 1（已登记）或 2（未登记）。0B54 单点更新不自行标记整份缓存已加载。

## 界面 0A28 的另一份位图

0A28 直接更新 Agent383 MycWarResultNotebook：p1 bits1..31 为资源行 1..31，p2 bits0..23 为资源行 32..55；p1.bit0、p2 高 8 位以及 p3/p4 均未读。结果写 Agent+14303+recordRowId，另设 dirty+210。

140D8C3E0 以资源行 r 创建初始槽 r-1，并在槽首保留 r-1。虽然记录随后按显示顺序排序，140D8B940 按保留 ID 查找并读取对应登记 bool，写为 UI 布尔值；140D8BF70 另将登记、资源有效性与任务条件组合统计已登记数。因此行号与网络 bit 的映射不依赖排序后的槽号。

当前 MYCWarResultNotebook 有行 0..55，其中 1..50 有名称，51..55 为空占位。0A28 和 0B54／55 分别更新界面标志与道具查询缓存，不应合并成同一内存字段。
