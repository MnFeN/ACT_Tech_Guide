## 数量表格的闭环

140E1E270 将 10 个拆分字段转交 AgentHousing120 的 141721570，构造 11 个 AtkValue。目标窗口 ID 来自 Housing，或 HousingInteriorPattern462 已打开的子窗口。当前 Addon 名称表 611 为 HousingWareHouseStatus；其独立名字函数 14161A3F0 和构造 14161A3A0 确认 vtable1422A9970，vf51 为 14161A490。

本机 ui/uld/HousingWareHouseStatus.uld 根 node3/4 标题为家具/庭具（Addon6849/6850）。根 node5 使用 component1007：子 node3 是仓库内（6845），子 node7 是已布置（6846）；X=200 是家具列，X=280 是庭具列。原生 vf51 写入如下：

| AtkValue | 内容 |
| --- | --- |
| 0 | **表格子节点**：9：已布置庭具<br>**网络值/分母**：p1.byte2 / p1.byte0 |
| 1 | **表格子节点**：5：仓库庭具<br>**网络值/分母**：p1.byte1 / p1.byte0 |
| 2 | **表格子节点**：8：已布置家具<br>**网络值/分母**：p2.low16 / p3.low16 |
| 3 | **表格子节点**：4：仓库家具<br>**网络值/分母**：p3.high16 / p4.low16 |

因此不是根据数量大小猜家具/庭具，也没有将仓库内和已布置两行倒置。

## 空间条件与图标

根 node9 使用 component1008。其子 node4 为能否搬迁（6848），node9 为能否内部整装（16425）。vf51 将 Atk5 写入家具搬迁 node5、Atk4 写入庭具搬迁 node6、Atk6 写入家具整装 node10。

- Atk4：庭具已布置+仓库数量，临时搬迁上限在庭具容量非 0 时显示 80，否则 0；使用 p1.byte3 的通过状态。
- Atk5：家具已布置+仓库数量，临时搬迁上限 600；使用 p2.byte2 通过状态。
- Atk6：同一家具合计，内部整装上限为 p4.low16 当前仓库容量；使用 p2.byte3 通过状态。

Atk8/9 分别保存庭具/家具搬迁 bool，两者联合决定搬迁图标；Atk10 决定内部整装图标。图标时间轴标签 101 为通过状态，102 为未通过；所有条件通过时根 node7 改到标签 17，隐藏警告区。数量文本通过 Addon16456 格式化，传入 bool 取反以选择状态格式；UI 不从数量自行重算三个包布尔。

庭具容量为 0 时 Atk7 提示 Addon16236“公寓与个人房间无法使用搬迁与内部改建功能。”；其他未通过组合用 16426，原始 SeString 包含搬迁/内部改建选择内容，不能只据 literalText 省略分支。ULD 说明 6843 标题仓库状况确认，6853 明确搬迁临时家具 600/庭具 80，以及私用以太之光和陆行鸟房例外。本包不提供这两个例外的单独数量。
