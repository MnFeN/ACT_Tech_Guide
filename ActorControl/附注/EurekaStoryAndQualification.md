# 优雷卡剧情与资格三字段：073A／073B／073C

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

三个入口共同操作 140B1F200 返回的状态包装对象，实际数据指针在其+0。140B1F210 创建 176 bytes 的数据，加载 EurekaStoryProgress；只在特定区域属性或 276/628 特例相关转区时保留／创建。旧 EurekaStep 只足以涵盖第一字段，不能把三个参数都命名为 step。

| 字段 | 内容 |
| --- | --- |
| 状态+1 | **073A**：p1 低 8 位<br>**单独更新入口**：无本组单独入口<br>**已证语义**：剧情进度 ID |
| 状态+4 | **073A**：p2 uint32<br>**单独更新入口**：073B.p1<br>**已证语义**：剧情资格所用元素等级缓存，后续同事件独立文本证据已确认 |
| 状态+8 | **073A**：p3 uint32<br>**单独更新入口**：073C.p1<br>**已证语义**：32 位剧情／场景资格旗标 |

其余 p4 及 Self 额外参数、Target 独立目标未读。单独 073B／073C 只读取 p1。

## 剧情 ID 及顺序表

140B1FD10 从 EurekaStoryProgress 行 0 开始沿首 byte 的 nextRow 链建立 rank[128]，位于状态+30h。140B1F5D0 取当前 ID，140B1F5F0 取某 ID 对应 rank（>=128 返回 0）；140B1F670 比较目标 rank<=当前 rank。

当前本机资源 92 行的链恰好 0→1→…→91→0，因此当前表的有效 ID 数值顺序与 rank 一致；这不改变程序实际通过表比较的事实。未载入或越界 ID 的默认 rank 也意味着不能无条件以任意网络 byte 直接比较大小。

073A.p1 变化会给 140 个对象+9Bh 置 1Ch，刷新 ZoneSharedGroupManager 并通知事件更新。140845160 在 ZoneSharedGroup 的 RequirementType4 中使用同一 rank 比较，确认它实际控制场景进度要求。

## 第二字段为何不能继续称掩码

140B1F610 直接返回+4 的 uint32。141A98B50 在剧情阶段 5/8/11/14 比较 3/5/13/17；141A996D0 的阶段 21/24/27/31/34 比较 21/23/25/29/35；141A99BA0 的阶段 47/54/57/59 比较 38/40/45/50。这些是数值资格门槛，没有按 bit 检查，撤回此前“后两项可能均为进度掩码”的保留猜测。

这组门槛与优雷卡元素等级阶段相符，因此推断为元素等级；当前尚未找到具名字段或具名脚本接口独立确认，文档明确保留此证据等级，不将推断装作符号已命名。返回 61721/61722 也未直接作为文本资源名解释。

第二字段变化仅给对象+9Bh 置 04h，请求后续刷新。

## 第三字段的真实 bit 消费

140B1F630 只在数据存在且 bitIndex<32 时测试+8 中的相应位。这确定第三字段是真正 32 位旗标，不是另一项等级值。

ZoneSharedGroup RequirementType4 除了剧情 rank 要求外，当资源附加字段非零，还要求该旗标 bit20。其他剧情消费者也调用逐 bit 读者，完整逐 bit 业务名尚待核；不把 bit20 直接命名为最终剧情完成或全部功能解锁。

第三字段变化给 140 个对象+9Bh 置 1Ch。现有 408 回放中本组无样本，本次为当前 EXE 静态分析与资源互证。

## 后续独立文本确认

三个原生等级阈值读者已分别定位到真实可露儿 CustomTalk 事件；本机实际 SystemTalk 明确“元素等级”，13 项门槛逐项一致。以上旧的“仅为推断／尚无独立确认”仅描述此前调查状态，已由 [EurekaElementalQualificationText.md](EurekaElementalQualificationText.md) 的实际事件、脚本与文本证据取代。原生 getter 仍未获得具名符号；073A.p3 的旗标缺口没有因此闭合。
