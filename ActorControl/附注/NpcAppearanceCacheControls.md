# NPC 外观覆盖缓存：06A4／06A5

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

这两项此前只记到“ENpc 缓存状态”。本次追到实际外观加载，确认其业务属于 NPC 换装／外观覆盖系统，包含 ENpcDressUp 表、本地服装及服务器下发外观数据。

| 类别 | 内容 |
| --- | --- |
| 06A4 | **参数**：p1=NPC 基础 ID，其余未读<br>**客户端行为**：将已有外观项置默认外观状态 3；旧状态 4 时立即触发应用链 |
| 06A5 | **参数**：全部参数未读<br>**客户端行为**：检查场景中已追踪 NPC，并按类型重新请求／加载外观覆盖 |

p1 是 ENpcBase 与 ENpcResident 共享的基础 ID，和场景 EntityId 不同。缓存与实例跟踪表通过基础 ID 及 GameObjectId 另外关联；没有把 p1 当作场景对象地址。

## 状态 3 的真实意义

14196F840 按基础 ID 在 map 中精确查找，不存在就返回；存在则将节点+E8h（value+C0h）状态设 3。没有清旧数据。若旧状态为 4，汇编 14196F879 将 RCX 设 node+28h 的 value 地址，尾跳 141A177B0；原先伪码漏显示这个隐式参数，现已按原始指令核对。

141A177B0 取得 ENpcBase 行（未就绪则异步加载），调用 141A179E0 在跟踪实例里匹配基础 ID 和 GameObjectId，再交 141A17B20 实际应用。后者在状态 3 时，武器、十槽装备、捏脸及相关字段使用 ENpcBase／NpcEquip 的默认值；状态非 3 且相应覆盖 mask 允许时才使用缓存数据。

状态 3 因此可命名为使用默认外观。旧状态不为 4 时，06A4 入口仅改变缓存，不能声称每次收包都会立即重绘。也没有销毁 NPC、删除记录或更改 NPC 服务器装备。

## 重新请求流程

14196FFC0 只检查缓存状态 0、2、3，跳过状态 1 及其他状态。每项在对象表中寻找 ObjectKind3（EventNpc），并要求场景对象 BaseId 等于缓存键。找到则置状态 4；未找到则将状态清 0。

若 ENpcResident.Map 为 5、6 或 7，走 141A178C0 的本地 ENpcDressUp 路径；其他情况发 ExecuteCommand2300，唯一参数为基础 ID。141A178C0 请求 sheet784 ENpcDressUp，回调 141A18310 必要时继续加载 sheet783 ENpcDressUpDress。两表当前分别 148、346 行，保存在 resources-enpc-dress-up-tables.json。

另一条普通网络数据路径是 140B4BAA0→14196F7B0→141A172E0：按包内+10h 基础 ID 匹配缓存，保存武器、十槽装备、26byte 捏脸及其他字段，状态置 2。原状态 4 时，再触发上述 ENpcBase／实例应用链。06A5 本身不携带这些外观字段。

## 证据与类型修正

分析中发现 ExdModule.GetSheetByIndex 原型只剩 self，导致许多伪码漏掉 sheetIndex。固定 FFCS 明确第二参数为 uint；特征唯一匹配 1405F3D00。按此修正原型并核 ASM 后，141A178C0 的 EDX=310h、141A18310 的 EDX=30Fh 明确对应两张换装表，未依据相邻函数猜表名。

现有 408 回放中两类别无样本；结论为当前 EXE、实际读取／应用代码与本机资源互证，没有描述成已在游戏中动态验证。
