# 0354 命令 10／064A p5.byte1：上赛季段位奖励提示门控

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

两个网络入口更新同一个 PvPProfile+78h（全局 142AE2CE4）：0354 命令 10 取 p2.low8；064A 类型 2 的完整段位分支（p2.byte0=8/9）取 Self p5.byte1。实际消费者 14107D260 在资料界面准备完成后，仅当 Agent 状态+418h 仍为 0 时检查这个 byte：

- byte==0：Agent+418h=1，+420h float=1.0，安排延迟提示。
- byte!=0：Agent+418h=2，跳过该自动提示。

14107C100 在界面有效时逐帧扣减上述秒计时；到 0 调用 141081130。后者要求状态恰 1，先置 2 防重复，再创建确认对话框，使用真实 Addon15450/15451/15452：

> 新的赛季开始了！您有上个赛季的段位奖励尚未领取。请前往狼狱停船场找赛季奖励发放员领取奖励。领取期限为当前赛季结束为止。

两个按钮为“打开地图”“关闭”。原始 SeString、控制码与本机中文保存于 resources-pvp-profile-byte78-dialog.json。不是 PvP 经验、当前星数、胜场、段位降级或系列赛奖励进度。

对话框事件 id8→14107B460→14107F2C0：取结果为 0 才构造地图标记并调用 AgentMap.OpenMap；非 0 直接结束。14107B460 普通界面事件 24 也会调用 141081130，但仍受状态 1 门控。14107C8C0 在相关界面状态 3 时把 Agent+418h 重置 0；不能把网络字段改动理解为每次立刻弹窗，已有 Agent 状态非 0 时该帧不会重新安排。

建议描述为“上赛季段位奖励自动提醒抑制值（0 可安排未领取提醒，非 0 跳过）”。原生使用零／非零，不逐 bit 解释。提示正文证明了提醒业务；不能只凭非零抑制就强称每个非零数值都是已经领取，或推断服务器是否区分无奖励资格与已领取。

## 证据边界

补查全局字段+14/16/18/1A/1C、+68/69、+78 的邻近绝对引用，新增直接消费者 14107D260。旁边 140C2F870 的引用实际指向+10h 三阵营 Rank 数组，不是+14h 未知旧统计字段。

随后沿 14107D260 的真实参数传递导出 14107D460、D6A0、D970、DCB0、DFD0、E390、E5D0 以及 14107FFC0；当前段位显示主要读+62..67 和+5A/5C，未从这些方法获得+68/69 的独立业务名。因此 0354 和 064A 整体仍保留剩余缺口，不能因本项确认而把整类自动计作完成。
