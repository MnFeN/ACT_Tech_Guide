# 萌宠之王设施启停与剩余强度：0518

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

## 布局与四参数

本包仅在 GoldSaucerDirector 内容 7 对象存在时处理。p1 完整 32 位选子命令 0..3；其他值忽略。p2 选侧、p3 选该侧设施，正常侧 0/1、设施 0..7；原生入口没有范围校验。每项记录 48bytes，基址 Director+7F0h+48*(8*side+facility)。

| 设施索引 | 内容 |
| --- | --- |
| 0 / 1 / 2 | **身份**：萌宠之门 A / B / C<br>**当前初始化强度**：1000 |
| 3 / 4 / 5 | **身份**：奥秘核石 A / B / C<br>**当前初始化强度**：5000 |
| 6 | **身份**：探索眼<br>**当前初始化强度**：1000 |
| 7 | **身份**：防御盾<br>**当前初始化强度**：1000 |

记录+0 为 active、+8 为 LayoutId、+0C 为当前强度、+10 为位置、+20 为受击提示冷却 float。命令 0 将 active=0，命令 2 将 active=1；写入先于查 Layout。Layout 存在才播放本方/敌方破坏时间轴 3/7 或激活时间轴 1/5，并输出设施提示。其余 p4 不读取。

本机帮助 HowToPage2190..2194 解释门、眼、盾作用及破坏后的“重启”，也明确奥秘核石不重启。因此命令 2 应写激活/重启，不能断言核石实际玩法中复活；原生没有按设施禁止该输入，且核石分支复用 4830/31 提示。

## 命令 1：位置特效

p4 是专用 vfx/lovm/eff 资源编号，位置来自设施 Layout。p4 恰 100 按比例 1 调用，其他值按比例 2 调用。不是通用 VFX 表行号，也不是读网络 p3/p4 为浮点坐标。比例不是秒数。

## 命令 3：原值覆盖与 HUD 互证

p4 完整 32 位原样写记录+0C；再按记录的 LayoutId 查对象，找到才同步其 Character+1B4h。固定 FFCS 对该通用字段标为 Mana；本玩法将其用于设施数值，不能照搬“玩家 MP”。缓存写入不依赖对象是否找到，没有 0..100 或 0..5000 钳制。

独立显示链明确该值是设施剩余强度：

1. 140E791F0 从记录+0C 原样返回 DWORD。
2. Agent1410D1650 按本方与对方的设施 3..5，写 NumberArray98[6..8]与[9..11]。
3. 原生注册 Addon425 HudMinionBattle 的主 creator140134670 实际创建_LovmHeader，ctor1416D6680 设置 vtable1422C5728；虚函数 52 是 1416D6E60。
4. Header 读相应六项，按 4000/3000/2000/1000/0 分档视觉；1416D7440 将每条宽度设为 current/5000.0*baseWidth，并画受损差值过渡。
5. 独立场景初始化 140E75C00 对核石赋 5000，其余设施 1000；Agent1410D07A0 初始化 HUD 六项也是 5000。

因此这里传当前剩余量原值，不是百分比，也不是本次扣减量。5000/1000 是当前客户端初始化/显示基准，不当成收包上限。没有将设施缓存等同 Character.Health；它们的底层存储不同。

核石索引 3..5 新值以 signed32 小于旧值，且记录+20 冷却<=0 时，播放 LOVM103 并置冷却 2.0。修复栈帧后得到的 140E73E30 逐帧伪码再次证明该冷却按 FrameDeltaTime 递减；这里 2.0 才是提示抑制的秒单位，不能与 VFX 矩阵缩放参数混淆。教程关卡 1 步骤 36 的标记还会在数值更新时被移除。
