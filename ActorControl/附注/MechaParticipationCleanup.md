# 0DFB：参与相关状态清理

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

旧说明“按事件 ID 切换参与状态”过于笼统。本机证据只显示清理既有状态，未发现这个收包设置 IsParticipating；不能用 p2==1 代表加入成功。

模块 141A2D7F0 要求+105CA readybyte，按完整 p1 事件行号查 map。找到后调用 141A6B7D0(event,p2==1)，直接 return1。这里不经过事件层 Flags&3==3 筛选，不能把 0DFC/0DFD 的门控照搬过来。p3..p8 及 target 没有此分支消费者。

## 共同前置清理

helper 先将 event+828C..82AB 的 32bytes 清零，再检查全局模块指针。包括 Contribution、个人进度及相邻子协议字段。它没有清最后的+82AC DWORD，不能写成“全部贡献/个人字段重置”。本机角色或 director 缺失时，p2==1 仍已经执行这 32bytes 清零。

## p2 完整值恰 1

要求本机和 MassivePcContentDirector 存在。module Flags bit5 置时，通过 141A26720(director,0)清 director 槽 0 的对象，再清该 bit；全局对应 byte 非 0 时清 Condition33。只有 PilotApplicationAccepted 位已经置起时，才清 module bits2..5，不能省略此条件。

阶段 4/5/6 时调用阶段虚 8，再以 141C56BF0(scene,2,2,1)写槽 2 状态 2；只有状态发生变化才写 dirty=1。阶段虚 8 的具体副作用见下文。

event+62AC 的 WORD 写 1，即 scene+623C byte=1、+623D byte=0。141C53CE0 更新在第一个 byte 非 0 时跳过本机目标位置推进；141C58660 用两 byte 协调范围提示/命令 3483 状态。因此这是结束对应场景位置/区域提示流程的复位，不能称为给角色添加参与状态。

## p2 所有其他值

IsJoined 置时清 module bits7..10；未置时不无条件清这些位。随后 141C553E0 遍历已注册对象，根据资源状态切换对象可见/交互路径。Type7 停用探查器的两层附加布局，清 scene+1939 第二层启用 byte；Type10 停用另一选择器的两层布局，清+19F9 和+1A00 字段。两者不等同于删除场景中的全部实体。

## 地图标记

上述分支完成后，阶段 3/4/5 仅将类型 3..7 的地图标记置 dirty；其余阶段将全部当前标记置 dirty。它是刷新标志，不是立即重新生成所有标记。

四参数边界与阶段回调现已闭合，将 0DFB 转为已核对。没有回放样本，不宣称已观察到运行时画面；也不为仅被清零的无名字段编造服务端业务名称。

## 阶段回调闭合

141A69E90 构造对七个阶段对象真实写入的虚表，从 14241B5B0 开始、间隔 50h，槽 8清理回调分别导出在mecha-stage-cleanup-virtuals.json。这里 4/5/6 可达，不能把任意相邻函数当成回调。

| 阶段 | 内容 |
| --- | --- |
| 4 | **槽 8 回调**：141C5F620<br>**具体布局请求**：缺省三槽 pending=4；槽 0=1，槽 1=4，槽 2 按 Accepted 位为 1 或 4 |
| 5 | **槽 8 回调**：141C5F700<br>**具体布局请求**：缺省三槽 pending=4；槽 0=2，槽 1=1，槽 2 按 Accepted 位为 1 或 4 |
| 6 | **槽 8 回调**：141C5F500<br>**具体布局请求**：仅调用 141C56BC0 设置缺省三槽 pending=4 |

缺省操作只改 pending 为 0 的槽，并置 dirty。141C56BF0 只在状态变化时写 dirty；调用结束后 0DFB 统一把槽 2 改成 2。

141C53670 更新按槽内布局 InstanceId 通过 LayoutWorld 取得 SharedGroup，pending1/2/3/4 分别转为 140706080(...,1,1)/(0,1)/(1,0)/(0,0)。这些是场景布局启用与过渡请求，不是角色的战斗 Status。状态处理后清 pending，并保留已应用状态以保持后续布局一致。

141A26720 的 director 槽 0 对象是特效指针：调用 140391030(vfx,1)写触发编号 1、140391940(vfx,0)清+1C0 关联指针，再清 director 保存的槽指针。它没有直接调用析构，不能简称“立即删除特效实例”。141C553E0 中的 140898020(object,0)则明确清 GameObject.TargetableStatus 的 IsTargetable 位；对象可见性还有资源状态及虚函数分支，不笼统称为销毁实体。
