# 浮点数值转换的汇编纠正：03A0／0358

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

本轮在追 0358 时发现主函数反编译的 signed 表达与实际指令不一致。为避免由局部变量类型传播制造错误语义，改以原始指令为准，并同步修正既有条目。

## 03A0

140B43D7A：mov eax,[p1]，将 32 位值零扩展至 RAX。140B43D81：cvtsi2ss xmm0,rax，执行 64 位有符号整数转浮点；由于上一步已零扩展，输入范围是 0–4294967295。因此协议意义是 uint32 数值转 float。

覆盖缓存的消费判断仍为 float>0；网络 uint32 的 0 不覆盖默认速度，其余值均为正值。FFFFFFFFh 会变成约 4.295e9 的正 float，不能把它解释成-1 并禁用。此前“signed int32，零或负数保留默认”的表述已撤回。

## 0358

本机路径 140B3CB17／34 分别 mov eax 加载 p3／p2；140B3CB2F／38 执行 cvtsi2ss xmm2／xmm1,rax，然后乘 0.1。观战路径 CB57–7E 采用相同零扩展和转换。两者均为 uint32 数值转换再缩放，不能将 p3 叫 int32。

这不改变 p1 为 EntityId、p4/p5 为额外本机状态的读取结论；两项浮点值已进一步确认为复活剩余倒计时及可复活阈值，见 ReviveCountdownAndMedals.md。

## 使用原则

本机指令已直接证明上述两项，不把这一纠正机械套到其他所有 float 字段。逐项区分 mov eax+cvtsi2ss rax、movsxd+cvtsi2ss rax、cvtsi2ss eax 和 movd 位重解释。主伪码当前保留原始工具输出，旁侧文档明确标注不可靠的 signed 表达，不通过编辑 C 伪码伪造工具证据。

0010 的 p2／p3 冷却时间和 00E2 的 Self p5 移动持续时间也由零扩展转换确认，补充显式 uint32 说明。000E 的死亡起点在被调函数内部另做转换，本表未把它机械改掉；0642 等被调方法中的转换亦需独立核指令。

VFX 管理器内部 remaining<=0 不启用计时的事实仍成立，但 B7／B8 网络参数只能产生非负数，故网络层只有 0 能以此方式关闭计时。高位取值不能当作负数哨兵。05F2 的逐帧严格<0 清理条件不变；只纠正入包取数的符号。

## 被调方法的独立复核

0642 阶段计时也确认 uint32：1417884F0 入口 141788518 以 mov ebp,r8d 保留 p2 并清 RBP 高位，14178854C／85B0 以 RBP 转 float。此前 signed 文字已纠正。

相反，000E 死亡起点 14090A420 在 14090A842 执行 movd xmm0,r15d，14090A847 执行 cvtdq2ps xmm0,xmm0：这是 signed32 数值转 float，确实不同于上述 uint32 零扩展路径。其原 int32 定义保留，并补实际指令依据。不能将所有整数到 float 都统一成 unsigned。
