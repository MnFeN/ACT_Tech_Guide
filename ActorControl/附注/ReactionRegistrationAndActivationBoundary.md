# 0E00 注册、资源配对与激活边界

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

继续 ReactionInteractionParameterVariants.md。此次追到独立初始化收包：当前实收 1418D71D0 的内部映射 0x17 直接调用 140B4DC10(payload)，后者取得 14198B320 管理器并调用 14198B6E0。这不是 ActorControl category17，也不把内部映射数字当线路 opcode。

## 初始化实际字段

14198B6E0 最多处理 8 项，类型 WORD 数组位于 payload+0，资源行 DWORD 数组位于+10h，三组 bool 字节数组位于+30h/+38h/+40h。遇第一个 type0 就停止；未知 factory 返回 0 不入 vector。141C43040 查询 factory 注册表后调用创建虚 1，141C430F0 分别保存 type WORD+8、resource DWORD+Ch 和三 bool+10h/+11h/+12h。

因此服务器初始化载荷同时提供类型和资源，不能把 ReactionEventObject 行号直接等同 factory 类型。对 140B4DC10 及 14198B6E0 的代码 xref 分别只发现上述实收入口／包装调用；当前保存的 14084C9D0 回放分发也没有调用它们。这里没有足够证据按回放记录长度猜出初始化 opcode，未这样做。

## 资源读取完成与激活分开

141C430F0 为指定 ReactionEventObject 行发起异步读取，回调 141C43360 累计子行数+38h，并按不同 Info 引用建立请求；+3Ch 保存不同 Info 数。141C43680 每次 Info 读取回调递增+3Eh，等于+3Ch 时置+40h=1。

141C43A40 读+40h，141C43A50 写+41h，141C437E0 读+41h。14198B4D0 在管理器尚未整体 ready 时，遍历每个+41h 为 0 的处理器调用虚 4，再重查全部+41h；全为真才置 manager+1D0h。+40h 是资源 ready，不等同+41h 初始化完成。

执行选择 141C437F0 要求+40h 且虚 12 许可；类型 4/5/7/8/9/10 虚 12 当前为常真方法，类型 3 的 141C965F0 额外要求 self+A8h/A9h 及本机角色存在。类型 7/8 虚 4 在资源 ready 后可从 WKS 模块缓存一个对象指针到+48h，再标初始化完成；并不在这里校验网络 type 必须等于资源 row。类型 9 虚 4 另按当前地域检查附加场景并缓存+48h，也不能由这个场景指针替所有类型命名。
