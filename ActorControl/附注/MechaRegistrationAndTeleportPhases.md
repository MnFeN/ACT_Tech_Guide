# 0DF9：报名预告/开放及地面支援传送窗口

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

模块 141A2D7F0 先要求 ready，直接更新 CurrentEvent。p1 不会选择目标事件，也不会让这个模块分支因 ID 不匹配而取消。后续事件转发虽做行号/Flags 比较，但 scene 对此类别 default、7 阶段虚 9return0，没有额外消费者。

字段写入要求 CurrentEvent 存在。2/7 的提示先于该指针检查：WKS 功能 8 已解锁且 manager+EC8 bit6 置位，就调用 10830 提示助手，即便 CurrentEvent 为空也可能提示。重复 2/7 没有此处的去重保护。p5..p8 及 target 未读取。

## 完整值与独立 helper 不能混淆

本收包先以完整 int 筛选 1..8，之后内层 char switch 才处理。因此 p2=257 不会执行 1。另一个 141A30E40 helper 直接接受 byte 子命令并执行相同字段操作，但这是独立调用路径，不能用其签名将收包规则改为 low8。

## 开放位和实际时间资格

1/5 不直接设置报名开放位，2/6/7 不自行更新报名时间。3/8 也不从 p4 读取结束时间；地面支援截止借用另已同步的 EventStartTimestamp+8260。

141A6B4F0 要求 Flags100 且 ServerTime<报名截止+826C。141A6B530 要求 Flags200 且 TeleportStart+8270<ServerTime<EventStart+8260，两端严格不等。所以开放位不等于永远可报名/可传送，时间字段也不会单独打开对应功能。

截止与传送开始的绝对服务器时间单位由前述比较、计时 UI 及 0DFC 专题交叉支持。+8268 报名开始字段与固定 FFCS 字段名/偏移相符；当前未发现该字段的直接显示消费者，保留“完整 DWORD 存储的报名开始时间字段”这一证据边界，不凭邻居时间反推隐藏动作。

本包只 OR 相关位，不清其他旧阶段位，不校验先后顺序或限制时间范围。1 和 5、2 和 7、3 和 8 在这些客户端动作上分别相同，不能擅自给同组命令编造不同成败状态。

没有 0DF9 回放样本。全部参数、完整子命令判别、当前事件目标与资格消费者已核对，转为已核对。
