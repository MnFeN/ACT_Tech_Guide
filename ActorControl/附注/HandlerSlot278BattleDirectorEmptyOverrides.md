# 0AF5：四种战斗相关 Director 的合法空槽

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

区别于前批短表越界，本轮四种实际构造的 Director 实例具有合法的槽 278，目标都为 140B22E80。该函数原始指令只有 `C2 00 00`，即 retn 0；它不读取 self 或任何传入参数，也没有副作用。空函数不保证返回寄存器为零，不能将其解释成固定 false 结果。

| 事件类型 | 内容 |
| --- | --- |
| 8009 TreasureHuntDirector | **实际创建函数**：140B02DB0<br>**安装主表**：1421A5040<br>**原生 ID 构造**：low16 与 80090000 组合 |
| 800D DpsChallengeDirector | **实际创建函数**：140B15AF0<br>**安装主表**：1421A59A0<br>**原生 ID 构造**：low16 与 800D0000 组合 |
| 8006 QuestBattleDirector | **实际创建函数**：140E0B2B0<br>**安装主表**：1421CE008<br>**原生 ID 构造**：low16 与 80060000 组合 |
| 801A FateDirector | **实际创建函数**：14177A670<br>**安装主表**：1422D4EC0<br>**原生 ID 构造**：low16 与 801A0000 组合 |

四个工厂先调用共同 Director 构造 140B6AF80，再在同一对象+0 安装各自主表；不是把附近其它事件表套进来。基 Director 主表 1421B0770 的槽 278 也是同一空函数。五张表前 300 项逐项核对，均为实际函数起点，270..294 之间未见独立表首代码装配引用；结合当前固定 FFCS Director 的 300 槽接口及真实继承构造，用来支持这里槽 278 的边界归属。前 300 项均有效本身并不独立证明表长度精确为 300，本文不作该延伸。

因此对于上述具体实例，0AF5 额外传入的 p2 低 16 位及 p3/p4/p5 不会在这个派生槽消费。不得推广为所有同类型后来替换的派生对象均为空；例如真正 ContentDirector 子类的同槽 140B70830 会要求本地地图标记 vector 指针，已另行核对。也没有证明服务器实际向这四类发送 0AF5。

原始证据：client/slot278-battle-director-probe.json、slot278-battle-director-prefix-controls.json、四个创建函数及 140B6AF80 的 C/ASM、140B22E80_nullsub_1433.asm。接口参照固定 [FFCS Director.cs](https://github.com/aers/FFXIVClientStructs/blob/80cb4a7b7e11a6702e2eb8839afd301a918c638e/FFXIVClientStructs/FFXIV/Client/Game/Event/Director.cs)。类别整体仍待其他合法派生目标核对。

## 战斗理符与部队理符

141A09E10 以 low16|80010000 经共同理符构造 141A075E0，随后安装 1423A9EF0；141A11300 以 low16|80070000 安装 1423AB208。两张具体派生主表的 278 仍是 140B22E80，前 300 项也逐项通过函数起点检查。新增这两类只涉及战斗/部队理符，不在此提前展开采集理符。

## MassivePcContent 的条件派生

工厂 141A23590 以 low16|800E0000 构造，但依据初始化参数首 DWORD 选择三种最终主表，不能只读取共同基类 141A24120 的 1423E2CB8：

| 初始化首 DWORD | 内容 |
| --- | --- |
| 1/2/5/6 | **最终主表**：1423E38A0<br>**合法槽 278**：141A2B120，地图标记 vector 填充 |
| 3 | **最终主表**：1423E4458<br>**合法槽 278**：141A2BBD0，原始指令仅 retn 0 |
| 4 | **最终主表**：1423E5010<br>**合法槽 278**：141A2C450，原始指令仅 retn 0 |
| 其他 | **最终主表**：无实例，工厂返回 0<br>**合法槽 278**：不建立槽语义 |

共同基类的 278 为 141A27170，也是 retn 0，但不能因此把第一组真实实例说成无作用。三张最终表和共同基表的前 300 项均通过函数起点检查；三个独立派生构造 141A2A0B0/141A2B620/141A2BD20 与工厂内安装相互支持。

141A2B120 用第二参数低 16 位传给 Agent helper140A77E90，第三参数则为完整 64 位本地 vector 指针：原始 141A2B136 将 R8 存 RDI，141A2B1A6 读取[RDI+8]、随后比较[RDI+10h]并以 80 字节步长追加记录，必要时调用 140AB4B10 扩容。这与已知地图标记接口相符；0AF5 包装却把 p3 DWORD 零扩展传 R8。不能将该 vector 指针解释成网络 p3 的已确认业务数据，也不能把其本地标记生成当成收到本包必定发生。这里仅核对签名与参数宽度，不展开相关生产场景的细分机制。

补充原始文件：141A23590/141A24120/141A2A0B0/141A2B620/141A2BD20/141A2B120 C 与 ASM，三个空函数的 ASM，以及更新后的 slot278-battle-director-prefix-controls.json（11 张表）。
