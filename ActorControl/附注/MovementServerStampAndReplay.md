# 00EC：后续移动上报附加标记与 00EF 本机合成记录

[ActorControl 分类与参数](../README.md) · [附注索引](README.md)

## 输入及唯一全局消费

00EC 仅把 p1 low8 写 byte142AF8D78，p2..p8 及 target 未读。不是非零转 bool。检查目标地址及前 7 字节的引用并按真实操作数宽度验证覆盖关系，得到主分支写和 14062BBC0 读两处；没有相邻 word/dword/qword 读取覆盖该 byte 的直接引用。该证据不宣称穷尽任意未知间接别名。

14062BBC0 以该 byte 为基础构造 ushort 附加 flags：controller+710 非 0 OR20h；子状态码为 2..4 OR10h；子状态码非 0 且内部+249 byte 非 0 OR100h。原输入位只能置 0..7，但后续结果可含 bit8。输入 bit4/5 已为 1 时，不会被本机条件为假清零；这是 OR 合并，不能把它写成由本机状态完全覆盖服务器字节。

该 getter 四个直接调用点全在 14062B170 和 14062B500，分别构造重同步及周期上报数据。收到 00EC 本身没有网络发送、坐标修改或切换本机行走/飞行模式。周期发送仍有位置、朝向及本机标志的跳过条件，不能说改字节就立即发送新包。

## 两种业务体布局

| 路径 | 内容 |
| --- | --- |
| 普通 14062B850 | **复制业务体字节数**：20<br>**本地内部消息编号 / 声明大小**：555 / 40<br>**附加 flags 位置**：body+6 ushort；坐标 body+8/+12/+16 |
| 扩展 14062B900 | **复制业务体字节数**：36<br>**本地内部消息编号 / 声明大小**：938 / 56<br>**附加 flags 位置**：body+10 ushort；首组坐标 body+12/+16/+20 |

扩展业务体前两个 float 对应当前/预测朝向，前一 flags 字在 body+8；第二组坐标在 body+24/+28/+32。这里只记录原生复制范围、内部消息号及声明大小，不将内部编号当实时网络 opcode，也不以这些大小推算未核对的外部封包头布局。

扩展重同步路径 14062B170 还无条件 OR40h；周期路径 14062B500 在前一 flags 字&4700h 非 0 时 OR40h。该位不只由 00EC 提供，不能从最终移动包 bit6 反推收到过 00EC。

## 位 6：实际发送模式分支

14062B900 检查 body+10 的 bit6：为 0 走 140481E80，为 1 走 140481EA0。两条路径经 141CFAB00/141CFAB30 到 ZoneClient.SendPacket141D00A10，唯一相关差别是其第五参数分别为 0/1，再原样下传到更底层。可以准确称为发送模式选择，当前没有证据称为 TCP/UDP 切换、可靠传输或立即 flush。

## 位 5：00EF 不一定是原始服务端收包

普通发送后 140631E30 读取 body+6.bit5；扩展发送后 140632010 读取 body+10.bit5。在本机记录开关 byte142AA895A.bit2 开启且 source 存在时，两者构造 24 字节的普通 ActorControl 形状：category=00EF，四参数全 0，并经 140849420 尝试加入记录器。该 wrapper 先通过 14084BEA0 的类别过滤，再调用 14084B4E0，以内部记录类型 735 和长度 24 写入。

因此回放中普通 ActorControl 记录的来源可能含本机主动合成，不可仅凭包族、category 和全零参数就认定来自真实网络收包。现有 00EF 的 90595 条观察保持原样；没有证据逐条区分来源，不能把它们全部归为本机合成，也不能全部归为服务端下发。00EC 在现有回放为 0 条，bit5 又可由本机状态独立 OR 出，故也不能把这些 00EF 记录归因于 00EC。

00EF 接收效果本身仍见既有类别文档：请求 ActionTimelineMove 在后续移动位置到来时收尾。本轮补充的是回放生成来源，并非更改该类别参数解释。

## 完成边界

本版客户端对 00EC 整个输入字节的保存、后续合并、业务体位置及已识别的本地位 5/6 消费均已确认。对未在客户端解码的位，只定义为按位保留并交后续移动上报的服务器附加标记，不为其虚构跨版本全局走路/飞行枚举。它与“存入未知字段且无肯定消费者”的条目不同，已有完整、可追溯的输出用途，因此按当前客户端行为记为已确认；服务端对其余位的内部意义不由此推定。

本轮还读取固定 Sapphire 源码的旧 MoveType/MoveState 定义及移动包布局，但其字段排列与本机 20/36 字节业务体不同，未用来套本字节的位名。该负面交叉检查不作本版协议语义证明。
